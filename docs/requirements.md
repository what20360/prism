## 当前版本 v1.14：有序流派、购买提示与三种对战规则

- 流派是可重复卡片的有序列表，例如伤害 → 射程 → 攻速 → 伤害。可以逐项移动、删除或编辑目标等级；追加同一卡片时目标等级自动递增。载入与预购不再根据属性生效优先级自动重排，前置不足时停在当前项等待，已有等级跳过。
- 删除五格快捷栏及数字键购卡。提供「收藏卡片」与「流派提示」两种方式：前者有独立收藏分类与屏幕边缘展开列表；后者在下一项可购时于固定屏幕边缘位置提示，点击即购买，自动开关开启则提示 180 战斗 tick 后购买，每一级重新等待三秒。暂停、倒计时、资金/前置不足或收藏方式下清零计时，不后台消费。
- 升级预设 v2 文件包含有序目标、收藏列表和购买方式；兼容导入 v1，旧五格转换为去重收藏。数值等级仍无设计上限，序列最多 2048 项作为文件和处理预算；购卡序号与属性生效优先级分别展示。

- 房主创建邀请前选择「固定装备」「限额构筑」「资源争夺」，连接后双方看到同一规则，当前对局中不能切换。固定装备保持相同标准装备且不能买卖卡片。
- 两种经济模式每回合双方均从相同基础属性、空构筑和 600 棱晶开始。准备阶段可买卖、装备技能、载入升级预设和调整预购；双方准备即锁定准备阶段操作，倒计时不消费，战斗中可继续购买。打开联机菜单不暂停。每回合重置钱包、构筑和场内实体，保留各自预购目标供下一回合补齐。
- 限额构筑无额外经济：造成/承受伤害、击杀和时间均不发钱，不刷新资源/怪物；出售只返还实付价 60%。资源争夺每战斗 10 秒给双方各 15 棱晶，按种子以 4–8 秒间隔随机刷新资源、8–14 秒间隔随机刷新怪物；刷怪最多同时 6 只，资源最多 24 份。怪物与两位玩家都敌对，独立索敌、命中和伤害规则对称。击杀怪物在死亡处掉落 18 棱晶；场内资源先接触者获得，双方都能使用磁吸，满血不消耗血球。PvP 伤害不产生棱晶。
- 经济、卡片账目、复活次数和预购队列各自独立。客机只能提交购买、出售、换装或计划请求，房主按真实价格、前置、余额、阶段和回合校验；不得由客机提交购买结果。快捷购买、命名预设与导入导出复用单人功能，预设仍不提供免费升级。
- 三种模式均沿用两胜制、120 秒回合与断线规则。网络协议版本提升，旧页面需要刷新后配对；网络会话不进入单人存档。

## v1.13：局内存档与联网 1v1

- 闯关与无尽模式支持 1 个自动存档和 3 个手动存档，主菜单与暂停菜单可读写、导入和导出 JSON 文件。测试场与实时 PvP 不写入局内存档。
- 自动存档每 10 秒尝试一次，并在暂停、返回主页、切换模式和页面隐藏时保存；已结束的局不会写成可继续的自动存档。手动存档独立保留，开启新局只更新自动槽。
- 保存完整战斗世界、房间进度、购买账目、随机状态与无尽补刷队列；读档不重新生成房间资源/敌人，清理设备输入和补帧计时。导入先校验版本、结构、有限数值、实体 ID 与卡片引用，失败不改变现有存档和当前局。文件上限 2 MiB。
- 1v1 是两位真人各用一台设备的联网模式。首次版本用浏览器直连：房主生成邀请代码，加入者生成回应代码，房主粘贴回应后建立连接；不要求账号或独立业务服务器。连接失败允许重新配对；网络无法直连时给出明确提示。
- 标准对决双方使用相同属性、枪/地雷与偏转/冲刺技能，不继承单人存档构筑。两胜制，双方准备后 3 秒倒计时，每回合 120 秒；死亡判负，超时比较剩余生命比例，平局重赛。回合重置全部临时实体，交换出场侧。
- 房主执行唯一权威模拟，另一方只提交经过校验的操作，不可提交血量、位置、伤害或购买结果。20 Hz 同步状态，30 Hz 上行输入；过期输入归零，双方有相同受伤无敌帧。打开菜单不会暂停联机战斗，支持认输/退出、再战与断线提示；连接中断不伪装成单人存档。
- 实时对局不支持中途存档恢复，单人存档与对战状态隔离。双方需保持游戏页面前台；不包含匹配服务、排名或商业中继服务。
- 升级预设保存名称、卡片目标等级和 5 个快捷栏位，独立支持 JSON 导入导出；最多保留 16 个命名预设，目标数值等级不设设计上限。预设只补齐升级目标，不会自动卖卡或降低现有等级。
- 预购按队列顺序逐级购买，沿用真实报价、前置与数值校验；可开关、调整顺序和移除。资金或前置不足时等待；只在单人战斗进行时购买，每帧最多处理 4 项，避免大量升级阻塞画面。队列随局内存档保存，新局清空。
- 快捷栏在单人战斗界面点击或用数字 1–5 购买一级；输入文字、菜单、主菜单和联网模式不会触发。手机通过“快捷购卡”展开按钮栏。预设文件上限 128 KiB，导入前校验，不自动购买。

## 历史版本 v1.12：再命中、资源与无尽模式

- 携带狙击手时，连发的轮数加成及伤害/射程代价均暂停生效，不排队补发；购买顺序不影响结果，卖完狙击手后恢复已购连发。切换构筑时清除失效的连发队列。
- 子弹及拖尾的颜色、亮度随剩余射程占总射程预算的比例变化：射程充足时明亮，接近耗尽时变暗变色，敌我保持不同色系。贯穿推进补充射程后可恢复相应光效。
- 新增“贯穿推进”：穿过单位后若仍有穿透，弹速及最高弹速乘 (1+0.12×等级)，剩余射程增加 60×等级。追踪转速提高至 1.35+0.25√等级弧度/秒，初速/最高速度倍率仍为 0.2/1。
- 弹丸与目标完全分离后，可以因追踪或弹射再次命中同一目标，每次正常结算伤害、穿透消耗与推进效果；连续留在同一碰撞体内只算一次接触。
- 取消清场和无伤通关的棱晶奖励。进入房间时随机放置血球和晶片一次，保留到拾取或离开房间；清场和持续刷怪不会重新生成房间资源。伤害类掉落卡仍按规则掉落。
- 磁吸核心解锁自动吸取半径（Lv n 为 100+80n），未购买时仅靠接触拾取；设置可关闭/开启已解锁的磁铁并持久保存。满生命时不消耗血球。
- 全部卡片均可逐级出售，按实付价 60% 返还；前置只限制购买，卖出不会自动撤销其他已购卡。
- 主菜单新增按世界种子启动的无尽模式。正整数层数 1–4、6–9 等在入场时一次生成有限敌人，数量随层数增长，逐属性检查层数强度上界，清场开启下一层传送门。
- 第 5、10、15…层入场便开放传送门，可以直接离开；敌人死亡后延迟补刷。随机强度有无界递减概率尾部，不应用层数强度上界；越晚补刷的敌人，其棱晶奖励倍率越低。主要战斗数值的均值随层数指数增长。
- 同种子与同输入的无尽生成/补刷可复现；重新开始保留种子并回到第 1 层。界面展示种子、层数、层类型、剩余敌人及补刷奖励倍率，不显示开发历史。

## 历史版本 v1.11：距离射程、追踪与函数化卡片

- 追踪弹初速为最终弹速属性 ×0.2，逐渐加速至 ×1；转向速度降为 `0.65 + 0.10√等级` 弧度/秒。保持原有射程代价和共享锁定。
- 狙击手可成长：Lv n 弹速 ×(1+2n)、射程 ×(1+0.6n)，仍同时仅存在一颗自有子弹。不额外降低追踪转速；高速带来的更大转弯半径自然降低追踪能力。
- 新增可回收成长卡“悬浮弹芯”：弹速 ÷(1+0.6n)。射程不因此减少，较低速度使弹丸停留更久、转弯半径更小，可组合追踪、射程、穿透、连发/霰弹形成飞剑构筑。
- 所有卡片的属性变化、价格和数值描述由函数及同一参数来源生成；下一级累计效果明确标注。成长卡不设设计等级上限，仅自动瞄准、自动射击、弹射、无视和手榴弹等纯功能开关保留一次解锁。主动技能升级获得相应效果成长。测试场等级编辑也不再限制为 20。
- 射程是累计飞行路径长度预算；直飞、追踪转弯、弹射和雷场内移动都按实际路程扣减。没有按固定存活时间到期的机制，因此同等射程下慢弹存留更久；现有命中、穿透、墙体和房间清理仍可提前移除弹丸。

## 历史版本 v1.10：主菜单与测试场

- 启动进入主菜单，提供开始闯关、测试模式、帮助、设置；存在未结束的当前局时可以继续本局。暂停菜单和结算页都能返回主菜单，返回时冻结世界，继续时不补算离开期间的时间。刷新不保存局内进度。
- 测试场与闯关会话隔离：固定靶机或敌人演练，可选开阔/掩体场景、目标数量/生命/护甲、无敌与自由购卡。靶机被击败后恢复供持续测试，不进入下一房间。
- 测试场提供总伤害、近 3 秒 DPS、平均 DPS 与击杀统计；可重置统计、清除弹幕和地雷、恢复生命与冷却、保留构筑重置场景或清空构筑。自由等级编辑仅测试场开放，范围 0–20 且遵守卡片自身等级上限；可绕过购买前置用于组合试验，普通闯关保留原规则。
- 测试模式不向普通闯关泄漏无敌、资源、卡片或统计；所有操作通过应用层模式控制器，核心战斗仍执行相同规则。游戏界面只显示可用操作与当前规则，不显示开发历史。
- 修复近战单位在障碍物拐角停滞：寻路视线使用与圆形单位一致的圆角距离判断，航点仅在下一段路径实际可通行时越过，避免合法贴角位置被错误当作完全封闭。

## 历史版本 v1.9：右键锁定与离线构建

- 桌面端左键只负责射击，不改变手动锁定；右键点击敌人固定目标，右键空白取消手动锁定，并阻止画布上的浏览器右键菜单。触屏维持点击目标锁定、点击空白取消，射击由右摇杆控制。
- 追踪卡保留低初速、转向和加速，并使最终射程除以 (1 + 0.20 × 等级)。同等级效果与购买顺序无关，说明和实际属性一致。
- 游戏页面只介绍当前规则，不包含开发、迭代或调整历史。开发记录保留在仓库文档中，不进入游戏界面。
- 卡片右上角独立展示价格，名称和等级位于左侧，优先级与效果位于其下；价格不足与前置状态仍有清楚区分。
- 提供可直接用桌面浏览器打开的独立 HTML，内置脚本、样式和程序化音频，无外部资源或服务器依赖。离线输出与在线站点使用相同入口和代码；运行时界面不显示构建记录。

## 历史版本 v1.8：统一锁定、装备技能与雷场构筑

本节取代下文旧版对应规则：

- 点击敌人固定手动锁定；点击空白或右键取消。手动目标死亡/离房后解除，否则不自动换目标。无手动目标时，在攻击方向前方 60° 半锥角内，优先选择可见、方向接近的敌人；自动瞄准和追踪弹共享锁定结果，手动射击仍由玩家控制。
- 地雷减速使用倍率 M≥1，区域内敌方弹速为自身速度/M；多个区域取最强倍率。爆炸、侦测、减速半径分别成长；无视卡使子弹不能触发或击毁地雷，但倍率增量只保留 45%。
- 弹射解锁后每次撞墙消耗 1 次穿透，消耗后须至少保留 1 次穿透，否则消失。连发在同一朝向依次发射，霰弹在多个朝向同时发射，两者总弹数相乘。追踪弹以较低初速发射、向锁定目标转向并加速，目标失效后沿原方向飞行或采用主人的新锁定。
- 狙击手增加射程与弹速，代价只为玩家同时最多拥有 1 颗子弹；枪、连发、霰弹、破片和夺回的子弹均遵守此上限。旧移速/生命惩罚取消。
- 玩家可购买偏转、狂暴、冲刺三个主动技能，但只能装备两个；J/K 与两枚触屏按钮对应槽位。购买时填入空槽，满槽后进入已拥有列表；在暂停菜单换装，每个技能保留自己的冷却，移除技能立即结束其主动效果。被动偏转力场不占主动使用次数。
- 狂暴暂时增加枪/地雷伤害、护甲、攻速和吸血；冲刺沿当前移动方向（静止时沿枪口）短暂加速，无穿墙与额外无敌。临时加成不写回永久卡片属性。
- 美食家由子弹有效伤害概率产生血球；掘金者由地雷有效伤害概率产生晶片。掉落可靠近拾取，不能通过无效命中刷取；切房清除掉落。手榴弹沿释放时移动方向移动，行程结束后自动引爆；迟钝增加本体生命与引爆延迟；破片发射继承玩家弹丸属性的径向子弹。
- 卡片购买页展示数字生效优先级：越小越先，同值按固定 ID 顺序；基础属性优先级 5–60，复合机制 100，最终生命比例 1000。
- 胆小鬼、玻璃大炮的生命代价按最终最大生命百分比结算，与购买顺序无关；合并旧重弹/重装/精确等重复姿态，保留有明确用途的基础成长卡。
- 敌人绕墙寻路、检查射线遮挡，单位柔性分离；移动保留摇杆力度，高速位移与子弹采用连续/分段碰撞避免穿墙和漏判。
- 手动瞄准使用当前逻辑 tick 的相机位置换算指针，避免连续移动、鼠标静止时因前一帧相机滞后导致方向抖动；选中目标也使用同一坐标基准。
- 子弹绘制为发光球体与受实际速度、轨迹影响的渐隐拖尾；锁定目标用独立框标突出；较长引爆延迟显示倒计时。卡片分类可折叠，刷新面板时保留折叠状态。

## 历史版本 v1.7：手动操作、构筑与视听反馈

以下保留上一版本背景，对应规则以顶部 v1.8 约定为准。

- 开局为手动瞄准、手动射击：键鼠使用鼠标方向和按住左键；没有鼠标方向时沿当前移动方向或上一次朝向射击。
- 自动索敌与自动扳机分别是局内升级卡，购买后默认启用，可在设置中暂时关闭；未拥有时设置不能绕过解锁。新局重新购买，浏览器偏好不能提供免费能力。
- 标为「可回收」的设置型卡可以出售一级，返还该级实际支付价格的 60%（向下取整），撤销效果并重算属性。普通永久成长卡不允许出售；依赖该卡的已购卡存在时不允许撤销，界面应显示依赖原因。
- 瞄准显示为更长的渐隐导向光束，移动显示为分离的推进尾迹；射击、技能和地雷冷却在角色周围用不同颜色的弧环表达。射击完整冷却低于 0.30 秒、技能低于 0.50 秒时隐藏对应冷却环，避免高速闪烁。
- 手机支持多点触控：左摇杆移动，右摇杆按住射击、拖动瞄准，独立地雷/技能按钮和菜单入口；拖动页面不应滚屏或缩放，旋转与失焦释放输入。菜单适配竖屏及安全区。
- 增加程序化 WebAudio 音效和循环背景音乐；第一次交互后启用声音，提供独立音乐/音效开关并保存偏好。声音不进入模拟层，隐藏页面时暂停音频。

## 1. 项目概述

### 1.1 一句话描述

一款 2D 俯视角、几何抽象风的地牢 Roguelike 射击游戏：**局内成长、无局外养成**，
以「模块可替换」为工程核心目标，而不是单纯做一个能玩的原型。

### 1.2 目标

1. 交付一个完整可玩的单局体验：5 层地牢 → 最终 Boss，单局约 15 分钟。
2. 引擎分层解耦：逻辑模拟、内容数据、渲染、输入、网络、存储互相可替换。
3. 文档与测试与代码同步，使第二个人能独立接手。
4. 为后续「无尽 / PvP / 指挥官 RTS」三种模式留出接入位，且接入时不改动核心逻辑层。

### 1.3 非目标（首个可玩版本明确不做）

| 非目标 | 说明 |
|---|---|
| 局外养成 | 无永久属性成长、无装备仓库、无货币系统 |
| 联网对战 | 已实现浏览器直连的真人 1v1；匹配服务、商业中继与更大规模联机后置 |
| 美术资源与音效 | 仅使用运行时生成的几何图形，无外部图片/音频文件 |
| 剧情与对话 | 无叙事文本系统 |
| 关卡编辑器 | 内容通过数据文件编写，无可视化编辑器 |

### 1.4 命名

- 产品名（对外）：**PRISM**
- 名称含义：几何、折射、抽象；同时隐喻「同一套核心逻辑经不同模式折射出不同玩法」

## 3. 目标玩家与体验支柱

### 3.1 目标玩家

喜欢 Roguelike 与弹幕闪避、愿意在 15 分钟内做多次构筑决策的玩家；支持键鼠、手柄与触屏。

### 3.2 体验支柱（用于裁决设计争议）

1. **决策 > 运气**：成长由玩家主动消费棱晶决定，不依赖随机抽卡。
2. **操作有回报**：收益按**伤害**换算（造成与承受两种），命中**内层**、穿透与高爆发自然转化为更高收益，鼓励技巧而非无脑刷。
3. **一局可读完**：15 分钟内完成一局的完整叙事弧（弱 → 强 → Boss）。
4. **弹道即语言**：敌方弹幕会被地雷减速与清除、会被偏转与反射——攻与防共用同一套弹道规则，靠理解弹道取胜而非堆数值。

## 4. 核心玩法

### 4.1 核心循环

```
进入地牢层
  → 逐个房间清理（移动躲弹 + 射击 + 技能）
  → 击杀即时获得棱晶
  → 随时打开升级面板（游戏暂停）消费棱晶 → 变强
  → 层内 5 间房通关 → 进入下一层
  → 5 层通关 → 最终 Boss → 结算
```

### 4.2 视角与操作

| 项 | 规格 |
|---|---|
| 视角 | 2D 俯视角。桌面基准视野 1920×1080，房间初版 3200×1800，相机跟随并夹紧；手机竖屏扩展纵向视野并将玩家保持在无遮挡区域，避免被底部触控覆盖 |
| 风格 | 矢量 / 几何抽象（圆、矩形、多边形、描边、发光），零外部素材 |
| 移动 | 单摇杆式：WASD / 方向键 / 虚拟摇杆 / 手柄左摇杆 |
| 射击 | 默认手动瞄准与射击；鼠标或右摇杆控制，自动操作分别购买升级卡解锁（见 4.3） |
| 武器 | 首发两把：枪（弹丸）与地雷（放置）；武器槽与切换见 5.6 |
| 技能 | 由升级解锁，初始 2 个技能位，可加点扩展（见 5.4）；绑定独立按键（含偏转/反射，见 5.7） |
| 升级面板 | 独立按键打开，**打开时游戏暂停** |
| 输入归一化 | 所有设备统一转换为 `InputState`（移动向量、技能触发、面板开关），逻辑层不感知设备 |
| 机制对称 | 玩家与**类玩家敌人**共用同一套战斗机制，差异仅在控制器与「能否加点」（见 9.5） |

### 4.3 瞄准策略（可替换）

当前默认手动瞄准；自动索敌必须拥有对应卡片，运行时在设置中切换：

| 策略 | 行为 |
|---|---|
| 自动锁敌（需卡片） | 自动瞄准射程内最近的敌人 |
| 朝向射击（手动无指针时的回退） | 朝当前移动方向射击；静止时保持上次朝向 |
| 手动瞄准（默认） | 鼠标位置或触屏右摇杆方向 |

> 架构要求：瞄准是**可替换策略**，新增策略不得修改射击系统的其他部分。

### 4.4 战斗规则（初值，均可在配置中调整）

| 项 | 初值 |
|---|---|
| 玩家基础生命 | 50 |
| 玩家移速 | 330 单位/秒 |
| 玩家受击无敌帧 | 0.5 秒 |
| 基础射速（枪） | **0.7 发/秒** —— 每发都要瞄准，压低射速让「什么时候开枪」成为决策；高射速是主要加点方向 |
| 伤害类型 | **单一「默认伤害」**（见 5.7.1） |
| 逻辑步长 | 1/60 秒固定步长，渲染插值 |
| 碰撞 | 圆形与轴对齐矩形为主，房间边界限制移动 |

### 4.5 局末流程与重开

**失败**

- 失败规则**由关卡数据配置**，至少支持两种：`死亡即结束` 与 `消耗复活次数后结束`。
- 复活次数是升级树中的一条加点线（见 5.5）。

**局末流程（失败 / 通关共用）**

1. 立即冻结世界（等同暂停，子弹与地雷倒计时全部停止）。
2. 弹出结算面板：用时、击杀数、核心命中次数、最高连杀、得分、累计棱晶。
3. 提供三个选项：`重开（新随机种子）` / `返回主菜单` / `查看本局加点记录`。
4. 不保留任何局内进度（无局外养成，见 1.3）。

**重新开始的统一行为**：结算后按 `R`、点击结算按钮，以及暂停菜单里的「重新开始」都走同一流程：关闭菜单与结算面板、清空残留输入与帧计时，回到新一局第一间房；保留玩家的操作设置。暂停菜单允许在本局尚未结束时重开。暂停、死亡或通关后不再采集战斗意图，也不补算暂停期间的逻辑 tick。

**中途退出**

- 任意时刻 `Esc` → 暂停菜单 → `放弃本局`（二次确认）→ 进入上表第 2 步的结算面板，并标记为「放弃」。

## 5. 战斗与局内成长系统

### 5.1 资源：棱晶（Shard）

- **无需拾取**：造成伤害的瞬间直接结算到玩家账户，配以浮动数字与音效位置（纯视觉反馈）。
- 资源不跨局保留，局内无硬性上限。
- 收益由「造成的伤害 × 敌人等级系数 × 连杀系数」加上「承受的减免前伤害 × 系数」决定（见 5.2）。

### 5.2 收益结算公式

```
输出收益 = round((实际伤害 + 溢出伤害 × 0.5) × tierRate × chainMultiplier)
受伤收益 = round(敌方来源的减免前伤害 × takenRate)
shardGain = 输出收益 + 受伤收益
```

**核心原则：收益由「伤害」决定，与「是否击杀」无关；输出与承伤都能换来成长。**

- 每造成 1 点实际伤害即产生收益：持续输出与单发爆发同样有价值。
- **溢出伤害按 50% 计入**：击杀时超出剩余生命的伤害仍算一份收益，奖励高伤害单发与爆发构筑。
- 因此内层（伤害 ×1.5）、多重射击、AOE 多目标、护甲穿透**都不需要额外的收益乘数**——它们通过伤害量自动转化为收益。
- **承受伤害也产生收益**，且按**减免前**的伤害计算（见 5.2.2），使防御构筑同样有经济回报。

**敌人等级系数（tierRate，棱晶/伤害）**

| 敌人等级 | tierRate |
|---|---|
| 普通敌人 | 0.10 |
| 精英 / 层守卫 | 0.12 |
| 最终 Boss | 0.05 |
| 召唤物 / 分裂体 | 0.10 |

**连杀系数（chainMultiplier）**

- 连续击杀间隔 < 3 秒时连杀数 `n` 递增，`chain = 1 + 0.1 × (n - 1)`，初始上限 **2.0**（可通过加点提升，不设硬顶）。
- 间隔超时或受伤导致连杀中断。

**房间奖励**

- 清空房间：+10 棱晶
- 无伤清空房间：额外 +5 棱晶
- 房间奖励是**保底收入**，设计上应占总收入 ≤ 40%（见 5.11）；主要收入来自伤害。

#### 5.2.1 判定细则（消除实现歧义）

**「受伤」的定义**：只有**生命值实际减少**才算受伤。被护盾或无敌帧完全吸收时不计入「无伤」，也不中断连杀。

**收益不区分击杀方式**：精准、技能击杀、环境致死、连爆都不再有独立乘数——它们的价值已经体现在伤害量上（内层 ×1.5 伤害、AOE 命中多目标、单发高溢伤）。

**内层不会重复加成**：内层只提供「伤害 ×1.5」，收益随之自动提高，不存在第二个「精准击杀系数」。

**「清空房间」的判定**：房间内所有敌人（含分裂体与召唤物）全部死亡；清场过程中新生成的分裂体同样计入。

#### 5.2.2 受伤收益（takenRate）

```
受伤收益 = 敌方来源的减免前伤害 × takenRate
```

| 规则 | 说明 |
|---|---|
| 计算基数 | **减免前**的伤害：护甲减伤之前、护盾吸收之前 |
| 来源限制 | **只计敌方来源**；自己布置的地雷、环境自伤一律不计（防止自伤刷棱晶） |
| 无敌帧 | 被无敌帧挡开、未成立的命中**不计**（不算被打中） |
| 护盾吸收 | **计入**：护盾是资源，被打穿同样算承伤 |
| 系数 | `takenRate = 0.05`（约为普通敌人 tierRate 的一半，保证「打人」仍比「挨打」划算） |
| 连杀 | 不乘 `chainMultiplier`；且受伤本身会中断连杀 |

- 设计目的：让「护甲 + 生命 + 护盾」的防御构筑也有经济回报，而不是纯输出流的陪衬。
- 溢出风险不作为缺陷处理：若某个防御流派收入过高，通过 `takenRate` 或敌人伤害数值调节。

#### 5.2.3 得分（Score）

得分**只用于结算展示与无尽模式排行，不参与成长**（成长只由棱晶决定）。

```
score += 实际伤害 × 1
每命中内层：score += 5
```

- 普通模式结算面板展示得分；无尽模式以得分为排行依据（首发为本地排行）。
- 首发**不做成就系统**，仅记录「核心命中数 / 核心击杀数」两项统计。

### 5.3 升级面板（暂停式）

- 打开即暂停；关闭即恢复。
- **购买以「卡片」为单位**：面板展示卡片，显示名称、效果、下一级价格、**前置条件**（见 5.9）。
- 购买即时生效，无需二次确认。普通成长卡不提供撤销；标为可回收的自动操作卡与姿态卡可以卖出，按该级实际支付价格的 60% 向下取整返还，并重算效果。
- **所有加点数值不设硬上限**：平衡由价格函数与正负属性捆绑承担（见 5.10）。
- **模式适用范围**：暂停式加点为《普通》与《无尽》模式专属；PvP 不可暂停，改用回合间隙加点（见 7）。

#### 5.3.1 卡片模型（价格函数 + 机制函数）

```ts
interface Card {
  id: string
  name: string
  priceFn: (level: number) => number;                  // 价格函数：只与购买次数有关
  effectFn: (level: number, attrs: Attrs) => Attrs;   // 机制函数
  priority: number;                                   // 复合顺序
  requires?: Prerequisite[];                          // 前置，见 5.9
}
```

- `priceFn` **只与购买次数有关**（`priceFn(level)`），不读取任何属性；卡片可以捆绑其他属性销售，但价格本身不被这些属性影响。
- `effectFn` 是**纯函数**：输入当前已解析属性，输出新属性；可做加法、乘法、条件判断与捆绑负面。

#### 5.3.2 属性解析管线

```
attrs = base
for card in sort(purchased, by = (priority, id)):
    attrs = card.effectFn(levelOf(card), attrs)
```

- 每次购买后重算一次；卡片数量 ≤ 几十，开销可忽略。
- **纯函数 + 稳定排序 = 确定性**：同基础属性 + 同购买列表 → 同结果，可回放、可单测。
- 卡片函数属于 `content/`；`core/` 只执行接口，不硬编码任何具体卡片（见 6.4 / 9.6）。

**卡片分类（初版）**

| 分类 | 内容示例 |
|---|---|
| 枪械与弹道 | 伤害、射速、弹速、射程、**穿透层数**、子弹大小、伤害范围、多重射击、暴击、**护甲穿透** |
| 地雷 | 伤害、爆炸半径、触发半径、**减速幅度**、**减速场半径**、同时存在上限、布置冷却、**不被子弹引爆** |
| 特殊被动 | 跳弹、破盾、命中回能、**子弹不引爆地雷**、**地雷本体免疫子弹伤害**、以及各武器的专属被动 |
| 防御 | 护甲、最大生命、护盾、护盾上限系数、无敌帧延长、**偏转/反射** |
| 恢复 | **吸血**、**吸盾**、护盾恢复速率 |
| 机动 | 移速、冲刺（若启用）、闪避冷却 |
| 技能 | 解锁技能、技能位、技能冷却、技能范围、**偏转力场半径/强度** |
| 特殊 | **复活次数**、棱晶收益加成、连杀上限提升 |
| 瞄准 | 解锁瞄准策略、索敌权重（可选） |

### 5.4 技能

- 技能**不是初始能力**，必须通过升级树解锁，解锁后进入技能位。
- 初版技能池：冲刺（位移规避）、护盾（短时免伤）、AOE 爆发（范围伤害）、**偏转/反射**（对抗弹幕，见 5.7.4）。
- **大部分技能带属性前置**，前置未满足不可解锁（见 5.9）。
- 初始技能位 2，可通过加点扩展（槽位数受操作按键数量限制，属结构约束，不是数值上限）。技能由升级解锁而非随机掉落。

### 5.5 复活

- 升级树的「特殊」分支提供复活次数（初版可加点至 2，数据可配置扩展）。
- 复活时清空周围敌人子弹，给予 2 秒无敌，连杀中断。
- 关卡数据可关闭该机制（如 Boss 战强制死亡即结束，可配置）。

### 5.6 武器系统

**设计原则**：武器 = 「发射器类型 + 弹药参数」的数据组合。新增武器只新增数据与行为插件，不修改逻辑层的武器框架。

| 发射器类型 | 首发 | 后续 |
|---|---|---|
| 弹丸类 projectile | **枪** | — |
| 放置类 placed | **地雷** | 炮台、陷阱 |
| 光束类 beam | — | 激光枪（持续命中，需视线判定） |
| 近战类 melee | — | 短距扇形 / 弧形判定 |

**武器槽与切换（初值，待确认，见 12.2）**

- 玩家携带 2 个武器槽（主 / 副），独立按键切换。
- 切换冷却 0.25 秒；切换不打断移动与瞄准。
- 两把武器共享升级树，但各自的弹道参数**独立成长**。

#### 5.6.1 枪（Gun）

发射子弹。以下参数**全部是加点方向**，且全部来自配置文件：

| 参数 | 标识 | 初值 | 说明 |
|---|---|---|---|
| 伤害 | damage | 10 | 单发基础伤害 |
| 射速 | fireRate | 0.7 发/秒 | 初始刻意压低；**无上限**，靠价格函数约束 |
| 弹速 | bulletSpeed | 700 单位/秒 | |
| 射程 | range | 560 | 约为视野宽度的 29%，超过半个房间要先接近 |
| 穿透层数 | pierce | 1 | 命中后仍可继续结算的次数；**1 = 命中即消失** |
| 子弹大小 | bulletSize | 14 | 碰撞半径 |
| 伤害范围 | blastRadius | 0 | 命中时 AOE 半径；0 = 单体 |
| 护甲穿透 | penetration | 0 | 抵消目标护甲值（见 5.7.2），与「穿透层数」不是同一属性 |
| 多重射击 | multishot | 1 | 每次发射的弹数（带散射角） |
| 伤害类型 | damageType | default | 全局唯一伤害类型（见 5.7.1） |

**「穿透层数」取代了早期的「子弹生命」**，语义如下：

- 单层敌人：每命中一个敌人消耗 1 层，穿透 2 表示可打穿第一个后继续命中第二个。
- 双层敌人（见 5.8）：命中外层消耗 1 层；穿透 ≥ 2 时可继续命中同一目标的**内层**并触发内层奖励。
- 子弹不再有生命值：**子弹之间互不碰撞**（见 5.6.3），也不存在「被打掉」的概念。
- 原本希望通过「子弹生命」表达的进阶手感，改用**特殊被动**承载（跳弹、破盾、命中回能等，见 5.3）。

#### 5.6.2 地雷（Mine）

放置型武器：在玩家当前位置布置，条件触发后引爆。用「布置换空间」，与枪的即时输出互补。

| 参数 | 初值 | 说明 |
|---|---|---|
| 伤害 | 30 | |
| 触发半径 | **120**（爆炸半径 × 0.6） | **敌方**单位或**敌方**子弹进入即触发（己方子弹不触发）。触发与减速场**共用一个比例变量** `MINE_PROXIMITY_RATIO`，调整时一起变 |
| 爆炸半径 | 200 | AOE 范围；**必须可视化显示** |
| 引爆延迟 | **0.08 秒** | 触发后几乎立刻爆炸，见下方数值依据 |
| 减速场半径 | **120**（与触发半径相同） | 范围内敌方子弹被减速；**自布置起常驻生效** |
| 地雷本体半径 | 30 | 可被子弹击中并击毁 |
| 减速幅度 | -40% 弹速 | 可升级（提升幅度 / 扩大范围 / 改为完全静止） |
| 地雷生命 | 1 | 可被子弹击中并击毁（见 5.6.3） |
| 同时存在上限 | 3 | **达到上限后继续布置会移除最早放置的一颗并放下新的**（FIFO，而非布置失败） |
| 布置冷却 | 2 秒 | 不消耗棱晶 |
| 伤害类型 | default | 全局唯一伤害类型 |

**引爆延迟的数值依据**：玩家踩中时距地雷中心约 120 单位，需再移动约 200 单位才能脱离 200 半径的爆炸范围。
以 330 单位/秒移速计算，0.08 秒只能移动 26.4 单位 → **无特殊加成时必然吃满伤害**；
只有极高的移速或冲刺类位移才能在触发后脱离。

> 设计意图：地雷范围必须**明确可视化**，玩家应当**绕开**而不是被动吃伤害。这里的「来不及躲」只针对已踩中触发的情形。

同一个 0.08 秒也决定了它的**清弹用途**：子弹触发后几乎没有反应时间，爆炸必然发生。

#### 5.6.3 子弹与地雷的交互

**原则：子弹之间互相无视；子弹只与「地雷本体」和「地雷爆炸」发生关系。**
（v0.5 起放弃「子弹对撞」机制：判定与平衡成本过高，收益不足。）

| 交互 | 结果 |
|---|---|
| **敌方**单位 / **敌方**子弹 进入触发半径 | **触发地雷**，进入 0.08 秒倒计时 |
| **己方**子弹进入触发半径 | **不触发**，可自由穿行（否则一开枪就会炸掉自己的雷） |
| 地雷减速场（与触发半径同范围） | 范围内**敌方子弹**弹速下降 −40%；对己方子弹不生效 |
| 倒计时期间子弹命中地雷本体 | 按普通伤害结算，扣除地雷生命 |
| 地雷本体在爆炸前被击毁 | **不爆炸**：无伤害、不清弹 |
| 倒计时结束且本体存活 | **爆炸**：对范围内敌人造成伤害，并**清除范围内所有敌方子弹** |
| 子弹 × 子弹 | **互相无视**，不做任何碰撞判定 |

- 爆炸清弹**直接移除**范围内的敌对子弹，不判定任何子弹属性。
- 减速场**默认常驻**：自布置起即生效，不限于倒计时期间（非倒计时期间本来也没有子弹需要减速）。
- 清弹是**对称机制**：敌方地雷爆炸同样会清除玩家的子弹。
- 减速幅度、减速场半径、倒计时长度、以及「改为完全静止 / 附加易伤」等变体，均为可加点项。
- 清弹职责因此只有两条路线：**地雷爆炸** 与 **偏转/反射**；不存在「用射速打掉子弹」的路线。
- 架构要求：`core/` 需要「可受伤放置物」与「区域清弹」两种效果，不需要子弹间碰撞。

**「不被引爆」加点与减速削弱**

双方各有一个对抗性加点：地雷方的「**地雷不被子弹引爆**」、子弹方的「**子弹不引爆地雷**」。

| 地雷方 | 子弹方 | 子弹是否触发地雷 | 减速效果 |
|---|---|---|---|
| 默认 | 默认 | 是 | **正常 −40%** |
| 默认 | 已点「子弹不引爆地雷」 | 否 | **正常 −40%** |
| 已点「地雷不被子弹引爆」 | 默认 | 否 | **大幅削弱**（−40% → −10%） |
| 已点「地雷不被子弹引爆」 | 已点「子弹不引爆地雷」 | 否 | **大幅削弱**（−40% → −10%） |

- 提炼成一条规则：**只要地雷方拥有「不被子弹引爆」，减速场就被削弱**；子弹方是否也点不影响结论。
- 削弱的作用是给这张加点标价：**用「免于被子弹清掉」换「减速能力下降」**，而不是白拿免疫。
- 削弱后的具体数值由配置给出（上表 −10% 为初值，可加点回补）。

#### 5.6.4 对抗性加点（地雷方 / 子弹方）

| 加点 | 归属 | 效果 | 代价 |
|---|---|---|---|
| 地雷不被子弹引爆 | 地雷方 | 子弹不再触发自己布置的地雷 | 减速场大幅削弱（见上表） |
| 子弹不引爆地雷 | 子弹方 | 自己发射的子弹不触发敌方地雷 | 无（但也不会因此清掉敌弹） |
| 地雷本体免疫子弹伤害 | 地雷方 | 子弹命中本体**不再扣血**，无法被击毁 | 特定被动，非默认；与其他被动互斥或叠加由配置决定 |

- 三个加点互不排斥，可以同时存在；结果按上表判定。
- **默认不免疫本体伤害**：任何子弹命中地雷本体都会扣血；免疫只能通过「地雷本体免疫子弹伤害」这一**特定被动**获得。
- 「不被引爆」只影响**触发（倒计时）**，不影响子弹对地雷**本体**的伤害结算：子弹打中地雷照样扣血，照样可以击毁它。
- 两者都在 `content/` 中以节点描述，`core/` 只读取标志位，不硬编码任何一方。

### 5.7 伤害、防御与恢复

#### 5.7.1 伤害类型（单一）

- 全局**只有一种伤害类型**，标识 `default`（普通伤害）。子弹、地雷、爆炸、撞击、Boss 技能统一使用它。
- 不按类型拆分抗性：防御只体现为**护甲**，减伤由其换算（见 5.7.2）。
- 数据层仍保留 `damageType` 字段（固定为 `default`），未来若扩展多类型无需改动结构。

#### 5.7.2 防御属性

| 属性 | 标识 | 初值 | 说明 |
|---|---|---|---|
| 最大生命 | maxHp | **50** | |
| 护甲 | armor | 0 | 防御值；减伤 = `护甲 / (100 + 护甲)`，因此**永远不会达到 100%** |
| 护盾 | shield | 0 | 临时生命，优先于生命扣除；**上限 = 最大生命 × 护盾上限系数**（见 5.7.3） |
| 无敌帧 | iframes | 0.5 秒 | 受击后的短暂免疫 |
| 复活次数 | revives | 0 | 见 5.5 |

**伤害计算公式**

```
有效护甲 = max(0, 目标护甲 - 攻击方护甲穿透)
减伤     = 有效护甲 / (100 + 有效护甲)
实际伤害 = max(0, 基础伤害 × (1 - 减伤))
```

- **结算顺序**：偏转判定 → 护甲穿透折算 → 减伤 → 无敌帧 → 护盾 → 生命。
- 减伤是护甲的**派生值**，不是独立属性：堆护甲的收益天然递减（100 护甲 = 50%，300 = 75%，900 = 90%），因此**不需要封顶也不会出现无敌**。

#### 5.7.2.1 护盾的真实行为（当前实现）

护盾不是「+最大生命」，而是一层**可被吸盾与卡片填充的缓冲池**，规则如下：

| 问题 | 当前答案 |
|---|---|
| 护盾怎么获得 | ① 买「护盾模块」卡（`shield` +10/级）**立即填充**该数值；② 吸盾（`shieldSteal`）按实际伤害的 N% 填充；③ `shieldRegen > 0` 时脱战 3 秒后按速率回填 |
| 上限是什么 | `护盾上限 = 最大生命 × shieldCapMult`。注意**上限随最大生命变化**：买「强化骨架」会连带抬高上限，但不会自动补满 |
| 上限初值 | `shieldCapMult = 1.0`，即默认上限 = 最大生命（50） |
| 伤害顺序 | 护盾先扣，扣完才扣生命；一次伤害可以把护盾打空并溢出到生命 |
| 与无敌帧的关系 | 无敌帧判定在**护盾之前**：无敌帧期间整次命中作废，不扣护盾 |
| 与「无伤」判定 | 护盾吸收计入承伤（算挨打、断连杀），因为护盾是资源；但**只有生命实际减少**才重置无敌帧 |
| 与减伤的关系 | 减伤先作用于伤害，**然后**才由护盾吸收。所以护甲越高，护盾越耐用 |
| 溢出 | 护盾剩余量不会转成治疗，直接丢弃 |
| 显示 | 有护盾时玩家外圈画一层淡蓝环；HUD 与角色属性页显示 `当前 / 上限` |

#### 5.7.3 吸血与吸盾（新增属性）

| 属性 | 标识 | 初值 | 上限 | 说明 |
|---|---|---|---|---|
| 吸血 | lifesteal | 0% | 无硬上限（溢出部分无效） | 造成伤害的 N% 转化为生命 |
| 吸盾 | shieldSteal | 0% | 无硬上限 | 造成伤害的 N% 转化为护盾，受护盾上限约束 |
| 护盾上限系数 | shieldCapMult | 1.0 | 无硬上限 | 护盾上限 = 最大生命 × 该系数 |
| 护盾恢复 | shieldRegen | 0/秒 | — | 脱战 3 秒后按该速率回复护盾 |

- 只对**实际造成的伤害**生效；伤害被减到 0 时不生效。
- 与内层判定（5.8）联动：命中内层伤害更高 → 吸血/吸盾收益同步提高，形成「精准 = 续航」的构筑路线。
- 三者均为独立加点分支，且可作为其他技能的前置（见 5.9）。

**结算公式**

```
吸血量   = 实际造成伤害 × lifesteal
吸盾量   = 实际造成伤害 × shieldSteal
护盾上限 = 最大生命 × shieldCapMult
护盾     = min(护盾 + 吸盾量, 护盾上限)
```

- 基数就是**实际伤害**（已扣护甲减伤、已计入护甲穿透），所以收益天然与「你的输出」和「对方的防御」挂钩。
- 吸盾**不受自身减伤影响**，但**受护盾上限约束**：上限 = 最大生命 × 系数，因此想堆厚护盾必须同时堆生命与系数。
- 设计意图：重度吸血玩家在小怪房可以几乎不躲；但 Boss 的单次高伤害大于吸血回复速度，近身硬吃仍会暴毙。

#### 5.7.4 偏转力场与反射（被动力场 + 主动窗口）

偏转是**连续力场 + 主动窗口**两层机制。

**被动：偏转力场（拥有偏转能力后默认存在）**

- 玩家周围存在半径 `deflectFieldRadius` 的力场（初值 220）。
- 场内的**敌方子弹**每帧受到**背离玩家**的加速度：`strength × (1 - d/R)²`，因此**越近改变越快**。
- 力场**不改变子弹归属**，只把弹道推弯；瞄得够准的高速子弹仍能打进来。
- 力场在「子弹移动之前」结算（见 architecture 5.4 的阶段 5.5）。

| 距圆心 | 相对推力 |
|---|---|
| 0.8R | 4% |
| 0.5R | 25% |
| 0.2R | 64% |
| 0（圆心） | 100% |

**主动：偏转 / 反射（默认按键 `J`）**

| 等级 | 名称 | 窗口内效果 |
|---|---|---|
| Lv1 | 偏转 Deflect | 力场强度 **×5**；接触的子弹**反向回射**且**归属转为玩家** |
| Lv2 | 反射 Reflect | 同上，且伤害 ×`reflectDamageMult`（初值 1.5） |

- 判定窗口：发动后 0.25 秒内有效（可加点延长）；冷却初值 6 秒。
- 只对标记为「可偏转」的子弹生效；Boss 的特定攻击标记为不可偏转（数据中区分）。
- **归属转换只发生在主动窗口内**；被动力场永远不改归属。
- **结算顺序**：力场推力 → 主动窗口归属转换 → 按 5.7.2 结算伤害。
- 架构要求：力场是「速度场」，窗口是「归属 + 方向」；两者都不引入独立物理系统。

### 5.8 双层判定（外层 / 内层）

**适用对象**：玩家，以及**类玩家敌人（rival）**——精英、层守卫、最终 Boss、PvP 对手。普通小怪为单层判定。
类玩家敌人与玩家共用同一套机制（武器、子弹、双层判定、偏转/反射、防御与恢复属性），只是由 AI 控制且**不能加点升级**。

| 层 | 说明 |
|---|---|
| 外层 shell | 默认命中区，正常结算 |
| 内层 core | 位于中心的小判定区（约占外层面积 20%），命中即视为「精准」 |

- 内层随实体移动；对会旋转的实体，内层随之转动。
- 渲染层必须让内层**可辨识**（中心亮点 / 内环 / 双重描边），不能只靠颜色区分（见 10 可访问性）。
- 内层判定由 `core/` 计算，渲染只负责表现。

**内层奖励（可配置）**

| 收益 | 系数 |
|---|---|
| 伤害 | ×1.5 |
| 棱晶 | ×1.5（由内层伤害 ×1.5 自动传导，无额外收益乘数，见 5.2） |
| 得分 / 统计 | ×2，并单独统计「核心命中数」 |
| 统计 | 记录核心命中数与核心击杀数（首发**不做成就系统**） |

- 打外层**不扣任何收益**：内层是纯正收益，避免玩家为了追核心而放弃输出。
- **对玩家同样成立**：敌人命中玩家内层时，同样按上表的倍率结算（对称机制，不是单向特权）。
- 外层半径、内层半径、内层面积占比、伤害/棱晶/得分倍率，**全部是可加点项**；上表数值只是初始状态。
- **AOE 只结算外层**：爆炸与范围伤害不判定内层，避免范围伤害白拿内层奖励。
- **内层判定为点对点**：子弹中心点落入内层判定区才生效；穿透层数决定能否在命中外层后继续结算内层（见 5.6.1）。
- **子弹在外层就停下**：因此「打到内层」必须由 `穿透层数 ≥ 2` 兑现——当弹道穿过内层且还剩 ≥ 2 层穿透时，结算内层（消耗 2 层）；否则只算外层（消耗 1 层）。
- **信息展示要求**：命中内层必须有明确反馈（命中特效 + 飘字），升级面板需写明「穿透层数 ≥ 2 才能打到内层」。规则若不可见，玩家会当作不存在。

### 5.9 属性前置（技能与节点的解锁条件）

- **大部分技能需要特定属性达到阈值作为前置**；前置未满足时节点可见但不可购买。
- 前置以数据描述，例如：`requires: [{ attr: "armor", min: 50 }]`。
- 初版示例：

| 目标 | 前置 |
|---|---|
| 偏转 | 护甲 ≥ 20 |
| 反射 | 已解锁偏转 且 护甲 ≥ 50 |
| AOE 爆发 | 伤害 ≥ 20 |
| 吸血 | 棱晶收益加成 ≥ 1 级 |
| 吸盾 | 护盾上限系数 ≥ 1.25 |

- 单个节点前置不超过 2 个条件；前置链深度不超过 2 层，避免构筑被彻底锁死。
- UI 必须展示「未满足前置」并说明缺什么（见 5.3）。

### 5.10 数值无硬上限：价格与捆绑约束

**原则**：所有加点数值（伤害、射速、弹速、射程、护甲、护盾、内层倍率、双层半径、穿透……）**一律不设硬上限**。
平衡不靠「封顶」，而靠两种属于**关卡设计**的手段：

| 手段 | 说明 | 示例 |
|---|---|---|
| 边际成本递增 | 第 n 级价格 `cost(n) = base × growth^(n-1)`；收益线性增长而价格指数增长 → 越买越贵、性价比递减 | 射速每级 +0.2 发/秒，价格 12 / 19 / 31 / 49 … |
| 正负捆绑（tradeoff） | 部分节点同时附带负面属性，买下即接受代价 | 「超载弹匣：射速 +40%，伤害 -15%」<br>「轻装：移速 +25%，最大生命 -20%」 |

- 价格曲线、`growth` 系数、捆绑卡片的负面属性，全部是**内容数据**，归关卡设计所有。价格本身**只与购买次数有关**，不读取属性（见 5.3.1）。
- 唯一的"上限"是数值本身的逻辑保护（生命不可为负、伤害下限 0），不属于平衡上限。

**关于数值溢出**：护甲公式 `减伤 = 护甲/(100+护甲)` 已保证减伤永远 < 100%，不存在「堆到无敌」的路径。
其余维度的溢出**不作为缺陷处理**——通过价格、怪物数值、卡片数值调节即可；探索出强力或有趣的极端方案，本身就是本作的核心乐趣之一。
验收只检查「一局内是否因数值失衡而无法推进或无法被击败」，不追求每条属性都被约束。

### 5.11 经济与节奏预算（初值，demo 后调整）

**节奏目标**

| 项 | 目标 |
|---|---|
| 单局总时长 | 15 分钟（12–18 分钟可接受） |
| 每房平均耗时 | 25–35 秒 |
| 一局加点次数 | 18–24 次 |
| 清房奖励占比 | ≤ 35% |
| 输出收益占比 | ≥ 50% |
| 受伤收益占比 | ≤ 20% |

**为什么限制清房奖励占比**：清房是保底收入。若它占比过高，玩家不提升输出也能变强，体验支柱 2（操作有回报）会被稀释。

**分层预算**

| 层 | 房间数 | 预期棱晶收入 | 预期累计加点 |
|---|---|---|---|
| 1 | 5 | ~240 | 4–6 |
| 2 | 5 | ~250 | 8–10 |
| 3 | 5 | ~255 | 12–15 |
| 4 | 5 | ~260 | 16–19 |
| 5 | 5 | ~270 | 20–24 |
| 最终 Boss | 1 | ~100 | — |

- 以上为**校验用目标区间**，不是硬性数值；实现后先跑通一局，再用实际数据校准。
- 敌人参数、卡片价格、Boss 血量等明细见 [docs/balance.md](./balance.md)。

## 6. 内容设计

### 6.1 敌人（行为原型，初版至少 5 种）

| 名称（工作名） | 行为 | 特点 |
|---|---|---|
| Drifter | 绕墙追踪与柔性分离 | 基础靶子，教学用 |
| Burster | 靠近后自爆 | 迫使玩家拉开距离 |
| Turret | 静止，周期性弹幕 | 需要绕后或远程处理 |
| Weaver | 横向摆动并射击 | 考验预判与走位 |
| Splitter | 死亡后分裂为 2 个小体 | 与「连爆击杀」系数联动 |
| Mirror（类玩家敌人） | 与玩家机制相同：持枪/地雷、双层判定、可偏转弹幕；AI 控制 | **不能加点升级**，强度由配置给定 |

- **判定层数**：普通小怪为单层判定；精英、层守卫、最终 Boss、Mirror 为**双层判定**（外层 + 内层，见 5.8）。
- 玩家的子弹可击毁敌方地雷本体；地雷爆炸会清除范围内的敌方子弹（见 5.6.3），高阶敌人应配有弹幕以体现该机制。
- 数值参数（血量、伤害、移速、射速、弹速）见 [docs/balance.md](./balance.md)；所有数值均可在不改代码的情况下重调。

### 6.2 Boss

- 每层最后一间房为「层守卫 **Warden**」——每层唯一的精英单位，压力高于普通房。
- 通关 5 层后进入**最终 Boss** 房，含多阶段（初版 2 阶段：弹幕 → 追击 + 弹幕）。
- Boss 需具备可读的攻击前摇提示（几何体的颜色/形状变化）。
- 最终 Boss 应包含**消弹场**类攻击（摧毁区域内的己方子弹），迫使玩家放弃正面输出、改用地雷与走位应对。
- 最终 Boss 为双层判定，内层随阶段变化位置，迫使玩家在躲弹中寻找输出窗口。

### 6.3 房间类型

| 类型 | 说明 |
|---|---|
| 战斗房 | 进入后关门，清空后开门 |
| 精英房 | 更强的敌人组合，更高棱晶收益 |
| 守卫房 | 每层第 5 间，层守卫战 |
| Boss 房 | 第 5 层后的最终战 |
| 安全房 | 每层第 1 间，无敌人，用于整理状态；第 1 层第 1 间同时作为教学房（见 6.6） |
| 空房 / 事件房 | 可选，初版可不做 |

### 6.4 数据驱动约束（重要）

所有内容必须是**数据 + 纯函数**（卡片的价格函数与机制函数），逻辑代码中不得硬编码敌人属性、关卡布局、升级价格：

- 敌人、技能、升级卡片、房间模板、层的构成，以及**武器与子弹参数**，均以配置文件描述。
- **卡片函数必须是纯函数**：无副作用、不读取 `Math.random` / `Date.now` / DOM / 存储，保证确定性与可测试性（见 9.4）。
- 加载时执行 **schema 校验**，配置非法应在启动时报错并指出具体字段（格式与校验方案见 9.6）。
- 修改内容不应修改 `core/` 中的逻辑代码。

### 6.5 关卡流程与房间连接

**房间连接（初版）**

- **线性推进**：安全房 → 战斗房 ×3 → 守卫房 → 下一层；无分叉、无地图选择。
- 清场后出口打开，走入出口即进入下一房间（不加载场景）。
- 层间过渡：一次性传送 + 0.5 秒淡入，不做独立场景。

**房间状态机**

```
idle → entered（进入房间，敌人入队） → combat（玩家离开入口区域后生成敌人） → cleared（开出口 + 结算奖励） → exited
```

- 入场时**一次性生成**该房全部敌人，不分波；出生点来自房间模板，且**不得在玩家 180 单位内**。
- **延迟刷怪**：切换房间时只把敌人放进 `pendingSpawns`，玩家离开入口 `ROOM_ACTIVATION_RADIUS`（140 单位）后才真正生成并进入 `combat`。这样进门瞬间不会被贴脸，也给了玩家看清房间结构的时间。
- 该状态必须在 HUD 上可见（`snapshot.awaitsEntry` → 「走进房间开始战斗」），否则空房间会被误判为故障。
- 关门期间房间边界同时对玩家与敌人生效。
- 清场判定见 5.2.1。

**房间结构与掩体**

- 每个房间由模板定义**静态墙体**（矩形掩体）：阻挡移动、阻挡子弹、不阻挡敌人刷新。
- **出生点不得落在墙体内**：内容层锚点必须与全部墙体布局保持净空；运行时再由 `core/collision.resolveSpawnPosition` 兜底，把重叠坐标沿最浅轴推出墙体并夹进房间边界。内容写错不能变成「敌人卡在墙里」。 
- 墙体需要为后续「子弹弹射」机制预留：碰撞按矩形边法线处理，`core/` 中保留 `reflect(bullet, wall)` 的挂点（首发不启用）。
- 初始射程 = 房间宽度的 50%（见 balance），使玩家在房间一侧无法直接打到另一侧，必须推进。

**Boss 房**

- 进入即关门；Boss 出场演出 1 秒（不可跳过）。
- 阶段切换由血量阈值触发（初版 50%）。
- Boss 战失败按 4.5 处理（默认死亡即结束）。

### 6.6 首次体验（教学）

- 第 1 层第 1 间为**教学房**：固定刷 2 个 Drifter，不刷其他敌人。
- 帮助与界面说明依次引导移动、手动瞄准射击、打开升级面板；不得提示开局已自动开火。
- 地雷教学延后到第 2 间房，用一条提示介绍放置与清弹。
- 无局外进度，因此不做「已学习」标记：重开新局会再次出现。

### 6.7 信息与可读性（辅助功能）

俯视角 + 大房间 + 窄射程的组合容易让玩家「不知道自己在哪、该往哪走」，因此以下信息是**必需**而非装饰：

| 元素 | 要求 |
|---|---|
| 房间边界 | 墙体以双层描边区分「墙」与「地面网格」；分辨率无关，不依赖颜色深浅辨认 |
| 小地图 | 右上角常驻，显示当前房间轮廓、墙体、出口、敌人位置、玩家位置与相机窗口；仅显示当前房间（不做全层地图，避免削弱探索） |
| 引导线 | 出口存在时，从玩家指向出口画一条虚线；仅指示方向，不替代寻路 |
| 暂停菜单 | `Esc` 打开，左侧目录（帮助 / 按键绑定 / 升级面板 / 角色属性 / 设置），右侧渲染当前分页；另有「继续」和「重新开始」操作；**所有暂停类页面都在这里** |
| 等待提示 | 房间尚未开战时提示「走进房间开始战斗」（见 6.5） |

**战斗信息反馈（飘字与指示器）**

战斗必须「看得见因果」，否则玩家无法从数值反推机制：

| 元素 | 表现 | 要求 |
|---|---|---|
| 造成伤害 | 白色数字，向上飘散 | 显示**实际伤害**（已扣护甲与护盾） |
| 溢出伤害 | 金色数字，带「溢」前缀 | 与普通伤害分开显示，让玩家理解溢出也产生收益 |
| 受到伤害 | 红色数字，带负号 | 显示自己实际损失的量 |
| 获得棱晶 | 青色 `◆N` | 伤害与承伤两种来源共用同一符号 |
| 目标信息 | 被命中的敌人上方浮出小卡：名称 / 当前生命 / 护甲 | 命中后短暂显示，不需要悬停 |
| 瞄准方向 | 长导向光束，近端清晰、远端渐隐，无端点圆点 | 手动与自动状态均显示当前枪口朝向 |
| 移动方向 | 三段分离的推进箭纹，移动时显示 | 与枪口朝向区分 |
| 射击 / 主动技能 / 地雷 | 角色周围青 / 紫 / 金弧环；触屏技能按钮同时显示冷却 | 射击完整冷却 <0.30 秒、技能 <0.50 秒隐藏对应环 |
| 蓄力/力场 | 力场半径以虚线圈绘制，主动窗口换色加粗 | 见 5.7.4 |

- 飘字是**纯表现**：存在 `world.floaters`，但**不参与** `hashWorld`，因此回放不受表现层影响。
- 不同类型必须用**不同颜色 + 不同字号**区分，不能只靠颜色（色弱可读性）。

**升级面板的信息要求**

- 每张卡必须显示：名称、当前等级、价格、**下一级的具体数值**（如「射程 +140（每级 +70）」）、以及**前置条件的中文说明**（如「前置：护甲 ≥ 20」）。
- 数值文案与效果函数必须**同源**：单属性卡由工厂函数同时生成 `effectFn` 与 `summary`，避免文字与实际效果不一致。
- 买不起时**不显示「棱晶不足」文字**，而是把价格本身变色（红）；前置未满足时价格淡化并单独标注原因。状态用视觉而非文案区分，减少面板噪音。

**角色属性页**

- 显示当前玩家全部生效属性：生命/护盾（含上限）、护甲与**换算后的减伤百分比**、移速、碰撞半径、复活次数、火力全参数与**理论 DPS**、吸血/吸盾/棱晶收益、偏转力场参数、地雷装备参数。
- 数值必须来自解析后的 `AttrSet`（派生值如减伤、DPS 现算），不允许读取卡片的原始配置。

- 以上信息全部来自只读快照，渲染层不得反向修改世界状态（见 9）。
- 小地图与 HUD 不得遮挡战斗区域中心，安全区（视口中心 ±240 单位）内不放置任何 UI。

## 9. 架构约束（硬性）

### 9.1 分层

```
src/
  core/       纯逻辑模拟（无 DOM）：ecs、systems、actor、weapon、spawn、rng、simulation
  content/    数据：enemies、weapons、upgrades、rooms、floors、schemas
  render/     Canvas2D 渲染器（只读快照）
  input/      设备适配：keyboard、gamepad、touch、replay
  storage/    本地配置持久化
  net/        传输接口（首发空实现）
  ui/         HUD、升级面板、结算面板（DOM 层，只读快照）
  app/        入口、场景、模式装配与生命周期
docs/
tests/
```

### 9.2 依赖方向（单向）

```
app → render / input / net / storage → core
```

- `core/` **不得** import 任何外层模块，不得引用 DOM、Canvas、`window`、网络 API。
- 渲染与 UI 只读快照，不得反向修改逻辑状态。
- 强制手段：`eslint` 的 `no-restricted-imports`，在 `src/core/**` 内禁止 import `render|input|storage|net|ui|app`；并用一个 `core-isolation` 测试扫描 import 语句作为兜底。

### 9.3 可替换点清单

| 模块 | 可替换为 |
|---|---|
| `render/` | Canvas2D → WebGL / PixiJS / 空渲染（测试用） |
| `input/` | 键盘 / 触屏 / 手柄 / 录制回放输入 |
| `net/` | 本地 / WebSocket / WebRTC |
| `storage/` | localStorage / 文件 / 内存（测试用） |
| `content/` | 整套内容换皮（不同主题的敌人与关卡） |
| `ui/` | DOM → Canvas UI / UI 框架 |
| 控制器 | `PlayerController` / `AIController` / 回放控制器 |
| 瞄准策略 | 自动锁敌 / 朝向 / 手动 |
| `app/` 外壳 | Web / Tauri / 移动 WebView |

### 9.4 确定性要求

- 逻辑层使用固定步长推进，输入驱动，不读取墙钟时间做判定。
- 随机数使用可播种的 PRNG，种子纳入局状态。
- 目的：可回放、可自动化测试、为后续联机同步留出可能。

### 9.5 统一 Actor 与控制器（机制对称的实现要求）

- 玩家与类玩家敌人是**同一个 `Actor` 类型**，共享武器、子弹、双层判定、防御与偏转逻辑。
- 差异只存在于**控制器**：`PlayerController` 读取输入，`AIController` 产出结构相同的**意图（intent）**。
- 控制器只输出意图，不直接修改世界状态；`core/` 只消费意图。
- 收益：AI 对手不需要第二套战斗逻辑；PvP 可直接复用；AI 还能作为测试替身驱动回归测试。

### 9.6 内容数据与校验方案

- **格式**：TypeScript 常量（`content/*.ts`）。类型即静态校验，编辑器可直接补全与跳转。
- **运行时校验**：启动时用**手写轻量校验器**（约 100 行，不引入运行时依赖）检查关键不变量：
  - ID 唯一（敌人 / 武器 / 升级节点 / 房间模板）
  - 数值合法（血量 > 0、价格 > 0、抗性 ≥ 0）
  - 引用存在（前置属性、房间引用的敌人、层引用的房间模板）
- **失败行为**：启动即失败，并输出精确路径，例如 `content/enemies.ts: Splitter.hp 必须 > 0`。
- 不引入 Zod 等运行时依赖，保持 1.3 的「零运行时依赖」约束。
- **卡片函数是纯函数**：不得访问 `Math.random`、`Date.now`、`localStorage`、DOM；随机一律走 `core/rng` 的可播种 PRNG。

## 12. 风险与开放问题

### 12.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 四模式总需求量大 | 工期膨胀 | 纵向切片优先；模式插件化；M5 先验证第二模式 |
| PvP / RTS 与动作玩法共用核心 | 架构被拉扯 | 核心只做通用的实体/移动/碰撞/时间，模式规则外置 |
| 内容量（25 房 + Boss） | 后期内容生产压力 | 房间模板 + 数据驱动，先少而精 |
| 「无需拾取」缺乏正反馈 | 手感稀薄 | 依赖浮动数字、连杀提示、面板节奏与音效位置反馈 |
| 武器与弹道系统（地雷减速/清弹、偏转/反射、双层判定） | 判定与平衡复杂度上升 | 首发只做枪 + 地雷；**不做子弹间碰撞**；双层判定仅在玩家与精英以上单位启用；数值集中在配置表 |
| 加点不设硬上限 | 极端构筑可能让某一路碾压 | 这是**玩法核心**（探索强力方案本身是乐趣），不是缺陷。溢出通过价格、怪物数值、卡片数值调节；护甲公式天然 < 100% 减伤 |
| 类玩家敌人与玩家同机制 | 平衡与 AI 实现难度上升 | 复用同一 `Actor`；AI 只输出意图；强度用配置等效「N 级加点」给定 |
