## 1. 优先级 P0：影响可玩性，下次恢复先做

### 1.1 房间僵持（窄射程 + 墙体 + 直线追击）

- **现象**：玩家射程 560，房间 3200×1800 且有掩体。敌人只会直线追击，被墙挡住就原地顶墙；玩家在墙后也打不到敌人，双方卡死。
- **为什么必须修**：这是当前唯一会让玩家「卡住无法推进」的问题，比任何数值问题都严重。
- **方案（择一或组合）**：
  - A. 敌人绕墙寻路（网格 A\* 或简单的「沿墙滑动 + 切向绕行」）；
  - B. 敌人被挡住超过 N 秒后瞬移到玩家附近（有预警）；
  - C. 房间清场条件放宽为「剩余敌人 < 阈值 + 计时到」。
- **验收**：在任意房间站着不动 60 秒，不会出现「双方都打不到对方」的状态。

### 1.2 敌人贴身没有分离力

- **现象**：多个 Drifter 会完全重叠在玩家身上，视觉上像一个。
- **方案**：敌我之间与敌人之间加一个软分离（每帧最多推开少量距离），不要硬碰撞以免卡墙。
- **验收**：三个敌人围住玩家时能看清三个轮廓。

### 1.3 触屏 / 手柄输入层不存在

- **现状**：只有 `input/keyboard.ts` 与 `input/pointer.ts`。
- **需要**：`input/gamepad.ts`、`input/touch.ts`，都只需实现同一个 `IntentSource`。
- **验收**：手柄能完成移动 / 放置地雷 / 技能 / 开菜单。

### 1.4 音效完全没有

- **方案**：WebAudio 程序化合成（不引入音频资源文件），事件挂点放在 `app/` 层订阅 `Snapshot` 变化，不进 `core/`。
- **验收**：射击、命中、爆炸、受伤、买卡、通关各有可区分的声音。

## 2. 优先级 P1：设计缺口，影响成品完整度

### 2.1 键位重绑定（requirements 4.6 的硬性要求）

- **现状**：`ui/sections/keys.ts` 里是**静态文案**，并注明「等 keymap 落地后必须改为读取配置」。
- **需要**：
  1. `storage/config.ts`：版本化读写 `settings.keymap`（含迁移函数）；
  2. `input/keyboard.ts` 从 keymap 读取而不是硬编码 `KeyE` / `KeyJ`；
  3. 按键说明页读 keymap，避免「改了键位但说明页说谎」。
- **验收**：改 `E` 为 `F` 后，按键说明页显示 `F` 且实际操作生效。

### 2.2 存档（设置持久化）

- **现状**：所有设置（瞄准/射击模式）只存在内存，刷新即丢。
- **需要**：`storage/config.ts` + `localStorage`，**只存设置，不存局内进度**（requirements 8 已定）。
- **验收**：切换为手动瞄准后刷新页面，仍然是手动瞄准。

### 2.3 切换武器（`Q`）与第二武器

- **现状**：`Q` 在 requirements 4.6 里，但代码里没有。地雷是常驻副武器，没有切换概念。
- **需要**：武器槽数据结构 + `Intent.weapon`，以及第二把主武器（激光或近战）。
- **验收**：`Q` 可在两把主武器间切换，卡片对武器分别生效。

### 2.4 技能 2（`K`）与技能池

- **现状**：只有偏转/反射（`J`）。requirements 5.3 里提到冲刺、护盾、AOE 爆发。
- **需要**：技能槽数组化（`Actor.skills`），`Intent.skill` 用槽位索引（已支持索引，但只处理 0）。
- **验收**：`J` / `K` 分别触发不同技能，HUD 显示两个冷却条。

### 2.5 复杂卡片需要更大的信息空间

- **背景**：当前卡片 3 行（名称+价格 / 效果 / 前置）刚好。加入复杂卡（多段效果、条件触发、与其它卡联动）会挤爆。
- **方向（未定）**：悬浮/点击展开一个详情抽屉，列表只留「名称 + 价格 + 一句话」，详情里放完整数值、每级曲线、前置、与当前构筑的交互提示。
- **验收**：一张有 4 个效果行的卡不会破坏面板排版。

### 2.6 数值待实测清单

见 `balance.md` 第 10 节。恢复开发后应先用真人试玩确认：

- 生命 50 是否太脆（第 3 层起是否一击必杀感过强）；
- 地雷触发/减速 120 是否让雷场变无脑；
- 力场 220/600、主动 ×5 的手感；
- Boss 2000 HP / 二阶段密度；
- 卡片价格曲线 `base × 1.6^(lv-1)` 在第 5 层是否过贵。

## 3. 优先级 P1：文档缺口（协同开发 / Mod 需要）

### 3.1 `docs/data-model.md`（数据结构和执行机制）

用户明确要求过，目前只有零散描述在 `architecture.md`。**已写好大纲，内容待写**：

1. **实体表**：`World` / `Actor` / `Projectile` / `Mine` / `Effect` / `Floater` 每个字段的类型、单位、谁写谁读；
2. **一 tick 的精确顺序**：把 `simulation.ts` 的 12 个阶段逐条展开，说明「为什么不能换序」；
3. **属性管线**：`base attrs → 卡片(priority,id 排序) → 最终 AttrSet`，哪些是派生值（减伤、护盾上限、DPS）；
4. **伤害管线**：唯一入口 `applyDamage` 的每一步与副作用（收益、飘字、连杀、无敌帧）；
5. **确定性与回放**：固定步长、PRNG、`hashWorld` 覆盖与不覆盖的字段（飘字不算）；
6. **快照契约**：`Snapshot` 是渲染/UI 的唯一输入，只读；
7. **扩展点清单**：加敌人 / 加卡片 / 加房间 / 加模式分别要改哪个文件，以及「`core/` 零改动」的边界。

- **验收**：一个没参与过本项目的人，只读这份文档就能加一张新卡片和一个新敌人。

### 3.2 Mod 支持（远期）

- **前提**：先有 3.1。当前 `content/` 是 TS 常量 + 纯函数，Mod 需要**数据化**（`effectFn` 改成 `{ op, attr, value }` 操作列表）。
- **已识别成本**：这一步无论做不做 Mod 都值得（热重载、关卡编辑器都需要）。
- **验收**：一个 JSON 文件能新增一张卡片，且不需要改 TypeScript。

### 3.3 战斗数值的手感文档

- 目前「为什么这个数值是这个数」散落在 `balance.md` 与 `devlog.md`。恢复开发后建议补一节「射速 0.7 的推导过程」这类内容，方便后续调参时知道边界在哪。

## 5. 已知技术债（不紧急但别忘）

| 项 | 说明 |
|---|---|
| 每帧全量快照 | `toSnapshot` 每帧重建所有 view 对象。实体上千时需要改增量快照（architecture 12.2）。 |
| 浮点确定性 | `hashWorld` 用 ×1e6 定点，物理仍是 f64。换语言/编译器后末位可能不一致。 |
| Node 18.16 | 低于 ESLint 9 要求的 18.18，安装时有 `EBADENGINE` 警告。 |
| 卡片 `summary` 手写部分 | 偏转/反射两张卡的文案是手写的，改数值时要手动同步（单属性卡已同源）。 |
| 菜单无键盘导航 | 只能用鼠标点分页，没有方向键/焦点环。手柄接入时需要先补这套。 |
