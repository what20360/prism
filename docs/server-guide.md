# PRISM 服务器与局域网使用说明

适用版本：v1.23（2026-11-04）。游戏本体继续由GitHub Pages发布；同一服务器程序既可在家中电脑运行，也可部署到公网主机。战斗由服务器执行，玩家浏览器不再充当战斗主机。

## 1. 最快开始：朋友在同一个局域网

1. 从游戏的“服务器与局域网”页面下载服务器包并解压，安装Node.js 22或更新的LTS版本。
2. Windows双击 `start-server.cmd`；macOS/Linux执行 `sh start-server.sh`。首次启动会执行 `npm ci --omit=dev` 安装锁定的运行依赖，需要网络。之后可离线启动。
3. 保持终端窗口开启。程序默认监听TCP 8787，打印本机地址、可用的局域网地址和建房授权码。若系统不允许读取网卡信息，可用Windows的 `ipconfig` 或系统网络设置查看IPv4地址。
4. 玩家打开GitHub上的游戏，进入“服务器与局域网”，输入例如 `http://192.168.1.20:8787`，再点击连接。
5. 连接后浏览房间；有建房授权码的玩家可创建房间，其他人直接加入。密码房需填写密码；不公开房间需输入房间ID。
6. 合作模式所有在线成员准备后，由房主/管理员开始；1v1双方准备后自动倒计时。

如果HTTPS页面连接局域网HTTP/WS被浏览器拦截，按浏览器提示允许本地网络访问。各浏览器的支持不同；通用兼容方式是直接打开终端显示的 `http://局域网IP:8787`，使用服务器包携带的同版本游戏。它与GitHub游戏使用同一套构建代码。请勿通过关闭浏览器安全功能解决问题。

Windows防火墙应允许所用网络中的TCP 8787。玩家设备必须能互访；部分访客Wi-Fi或开启客户端隔离的路由器会阻止局域网互连。

## 2. 从源码启动

```bash
npm ci
npm run build:all
npm run server
```

`build:all`生成前端 `dist/` 与后端 `dist-server/server.mjs`。仅修改后端时可执行 `npm run server:build`。打包可执行 `npm run server:package`，输出 `dist/server/PRISM_server.zip`；不要把运行数据目录加入发布文件。

本程序是所需的多人服务器，不使用Vite开发服务器。停止终端中的Node进程即停止服务，Ctrl+C会尝试先保存合作进度。

## 3. 局域网搜索如何工作

网页没有通用的UDP广播接收或网卡枚举接口。本实现没有假装扫描整个子网，而是使用一个发现入口：

- 服务器监听UDP 47873，在 `239.255.77.73` 多播组响应PRISM发现查询。
- 点击搜索时，网页向“局域网发现入口”的 `/api/discovery` 发起请求，服务器用临时UDP查询端口收集同网段回应，约0.9秒后返回地址列表。
- 在开服电脑的GitHub游戏中，默认发现入口为 `http://localhost:8787`；在服务器提供的局域网页面中默认使用当前服务器。
- 手机上没有本机发现程序时，需要先填写一台已知局域网服务器的IP，或直接打开它的局域网游戏入口。发现其他服务器无需再逐一输入IP。
- 多播通常只覆盖同一局域网，不跨路由器；VPN、容器网络、无线客户端隔离或防火墙可能限制发现。UDP发现失败不影响手动输入地址。
- 服务身份仅用于识别，不把发现回应当成授权。连接后仍需实际协议握手和玩家凭证。

公网部署默认关闭发现功能；如确实需要，显式启用 `PRISM_DISCOVERY=on`。允许发现时，请仅在可信网络中开放发现接口与UDP端口。

## 4. ID与身份备份

首次连接某个服务器会自动签发 `P-...` 玩家ID和随机私有凭证，无需注册密码账号。显示名可以重复，公开ID不能用来登录他人席位。

身份按服务器地址保存在当前浏览器。点击“备份玩家身份”导出JSON；换设备或浏览器后通过“恢复玩家身份”导入，再连接原服务器。备份内含登录凭证，应自己保管。GitHub页面与局域网页面属于不同浏览器存储来源，切换入口时可用备份迁移身份。

服务器只保存私有凭证的SHA-256哈希。新连接使用同一身份时替换旧连接，旧页面停止自动重连。服务器数据目录丢失后无法识别旧身份；仅有公开ID不能恢复。

更换服务器地址不会自动把已有凭证发送给另一个地址。需要迁移时由玩家明确导入身份备份。服务器身份发生变化时客户端拒绝静默复用旧凭证。

## 5. 建房与房间权限

默认 `PRISM_CREATE_POLICY=key`：创建房间需要终端显示的授权码，加入公开房间不需要该码。授权码保存在服务器数据目录，也可通过环境变量覆盖。每个ID最多拥有一间房，默认全服最多8间房、32条连接。

| 权限 | 房主 | 管理员 | 玩家 |
|---|---|---|---|
| 自己购买、准备、使用技能 | 是 | 是 | 是 |
| 开始/暂停合作、重开 | 是 | 是 | 否 |
| 移出/封禁普通玩家 | 是 | 是 | 否 |
| 管理其他管理员 | 是 | 否 | 否 |
| 分配权限、转让房主 | 是 | 否 | 否 |
| 导入合作进度、关闭房间 | 是 | 否 | 否 |
| 导出自己所在房间的合作进度 | 是 | 是 | 是 |

房间权限由服务器检查，界面隐藏按钮只是辅助。管理员不能管理房主、同级管理员或自己。房主离线60秒后，有在线成员时优先把管理权交给在线管理员，再交给其他在线成员；战斗模拟仍在服务器上。主动离开则立即交接。

“关闭房间”会释放房间与保留席位；离线席位占用人数上限，可由管理者移除。封禁按稳定ID记录。清理浏览器后新建身份不属于强认证实名封禁，所以此系统定位为私人朋友房；需要公开运营时应另接正式账号和防滥用体系。

## 6. 重连、存档与退出

管理者可修改“房间与存档名称”，导出文件名和内部名称随之更新；导入时保留原存档名。

- 短暂断线自动重连，凭证恢复相同角色、钱包与升级。输入超过350ms未更新会归零，技能/锁定等边沿事件不会每tick重复执行。
- 合作可选择掉线暂停；所有人离线时服务器不推进战斗。1v1缺少在线选手时停止推进，60秒仍未回来的选手按弃权处理。
- 服务器每10秒保存合作世界与ID席位映射、权限、密码哈希和封禁名单；管理操作和正常退出也触发保存。进程崩溃可能损失最近一个保存周期。
- 重启服务器后合作房间暂停，全部成员按离线处理，原身份重新连接即可恢复。1v1回合状态不跨服务器进程重启恢复。
- 无在线成员的房间默认保留7天；到期释放。长期停服前可额外导出合作JSON备份。
- 合作存档导入需房间暂停且只有创建者。旧存档没有服务器ID映射，多人存档必须在密码房导入；创建者继承原主持者角色，其余角色为待认领席位。队友凭密码加入时可填写原角色编号，否则自动认领一个空席位。已经绑定的玩家席位不能通过公开编号接管。
- “断开服务器”会尝试主动离开当前房间；返回主菜单或关闭页面则保留离线席位，以便恢复。需要彻底释放时使用房间内的“离开房间”。

## 7. 公网部署

在云主机上按源码步骤运行，建议用进程管理器或容器保持进程运行。GitHub Pages继续发布前端，玩家输入你部署的HTTPS地址。

公网使用HTTPS/WSS，建议通过Caddy或其他反向代理终止TLS：

```caddy
prism.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

将 `PRISM_PUBLIC_URL=https://prism.example.com` 传给服务器，确保主机名检查与代理域名一致。GitHub游戏默认来源 `https://what20360.github.io` 已允许；若前端换域名，用 `PRISM_ALLOWED_ORIGINS` 设置允许的来源列表，逗号分隔。不要使用通配来源。

Docker可从完整源码构建：

```bash
docker build -t prism-server .
docker run --rm -p 8787:8787 -v prism-data:/data \
  -e PRISM_PUBLIC_URL=https://prism.example.com prism-server
```

容器桥接网络下不保证多播发现；普通公网连接不依赖发现。Linux局域网需要容器多播时，可自行采用主机网络。持久卷必须允许容器用户写入。

## 8. 环境变量

| 变量 | 默认值 | 作用 |
|---|---|---|
| PRISM_PORT | 8787 | TCP服务端口 |
| PRISM_HOST | 0.0.0.0 | 监听地址；仅本机测试可用127.0.0.1 |
| PRISM_DATA_DIR | .prism-server | 身份、建房码、合作进度与权限的持久化目录 |
| PRISM_SERVER_NAME | PRISM 私人服务器 | 大厅显示名称 |
| PRISM_CREATE_POLICY | key | key需授权码；open允许已建立身份的玩家创建 |
| PRISM_CREATE_KEY | 自动生成并持久保存 | 覆盖建房授权码 |
| PRISM_PUBLIC_URL | 无 | 公网代理域名，参与主机名检查 |
| PRISM_ALLOWED_ORIGINS | https://what20360.github.io | 允许连接的前端来源；服务器自身来源也可用 |
| PRISM_DISCOVERY | 局域网默认开启，设公网URL时默认关闭 | on/off显式控制发现 |

不应把真实授权码、身份凭证、数据目录或TLS私钥提交到GitHub。源码已忽略运行数据和生成的构建目录。

## 9. 性能与同步

服务器60Hz模拟、10Hz显示同步，客户端最高30Hz上行输入且保持100ms心跳。网络不再发送完整存档：静态地图与不变字段不重复发送，实体按新增/变化/删除更新，玩家只接收自己的私有构筑。项目使用WebSocket压缩，5秒关键帧及按需重新同步；队列过大时暂停追加快照，避免无限积压。

客户端只对显示坐标进行插值和重建拖尾。伤害、碰撞、属性成长与随机数均由服务器计算，不因显示量化改变。显示插值增加约一个网络帧的延迟，目前没有本地移动预测或PvP回滚补偿。

可通过 `npm run bench:sync` 查看固定五人弹幕样本的数据量、压缩量与编码时间。它是可重复的数据量基准，不代表任意网络线路或最高无尽层数都能稳定运行。
