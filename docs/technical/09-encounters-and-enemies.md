# PRISM 技术手册（九）：遭遇编队、突击敌人与继电站

当前实现：v1.28（2026-11-06）。设计依据与尚未开发的设想见[敌人与关卡研究](../design/encounter-roadmap.md)。本篇说明实际代码行为；游戏帮助只说明现行玩法。

## 1. 关卡与遭遇生成

`content/levelSets.ts` 为闯关和无尽注册五种普通布局：折光回廊、交错屏障、四柱工坊、折光继电站、交错铸造场；原盘丝洞和安全屋继续保留。新增布局均使用原房间尺寸与传送门，可由现有圆形碰撞和可见图导航。

`content/encounters.ts` 定义四类主题及角色序列：掩体夹击（游猎、炮台、突击、追击）、重甲护送（卫士、灼线、追击、炮台）、引爆窗口（自爆、游猎、追击、炮台）、电弧拉扯（电弧、突击、追击、游猎）。可用成员先受 `dungeonEnemyPalette` 或无尽层数限制，角色按照序列循环且每波突击者不超过两个。出生点按左右两区放置，继电站前几名守军在装置附近；每个候选检查墙体、入口距离及已分配敌人的空间。

`content/dungeon.ts/buildDungeon` 按世界种子确定布局和主题，记住最近两个主题以避免重复，沿用七档难度的数值、数量与波次公式。首波继电站用两个现有生成槽替换为继电器，而不是在预算外添加怪；设备在多波间保留，后续波不重复生成。盘丝洞最终Boss及前置波不经过主题替换。

`app/modes/endless.ts` 用种子决定四主题循环的起点和方向，按层数选择，最近两层互异；当前主题随 `room.design.encounter` 序列化。每个守军仍由 `rollEndlessEnemy` 生成和附加词条，有限层逐属性夹紧，开放层使用无上界长尾；主题不会裁剪开放层的怪物属性分布。补刷依据同主题及已有随机状态进行，突击者同时最多两只，**不复活、补刷继电器**。补刷按在线活玩家位置和存活实体避免生成在身边或重叠，继承既有收益递减公式。设施占初始化总槽，敌人数显示排除设施；收益递减仍以房间初始总槽数为分母。

## 2. 继电器

继电器是 `behavior: 'relay'` 的可受攻击实体，基础生命90、半径38、无攻击、无词条。单人和合作都由服务器/核心管理；各武器、地雷与锁定通过原伤害接口处理，不要求互动按键。`core/systems/encounter.ts/relayAssignments` 对每个存活继电器找720距离内且视线不被墙阻挡的存活非首领敌人，按距离、ID排序取前两名；多设备覆盖同一目标时选择最近设备，平局选低ID，不叠加。`damage.ts` 在计算目标护甲时额外加35，不改永久 `AttrSet`，拆除、移动出范围或墙体遮挡后即刻失效。

继电器受到的伤害不会产生棱晶、分数、吸血、击杀计数、连杀或击杀掉落；它自身也不生成奖励。战斗日志飘字仅用于显示击中反馈。`room.ts/updateRoom` 在判断下一波或清场时忽略存活设备；跨波设备维持生命，最后一波守军清空后设备关闭并移除。无尽开放层其死亡不会加入补刷队列。`coop.ts/scaleRoom` 排除继电器和突击者的复制，防止多人扩编堆叠设备或突进预警。

`toSnapshot` 输出 `supportRelayId` 和包含生效加成的目标护甲。渲染器用设备与守军之间的连线、圆环和不同颜色显示；对同一房间的所有观察者计算相同。客户端只绘图，不能授权护甲或结算经济。

## 3. 裂隙突击者

`content/enemies.ts` 定义生命75、基础护甲10、移速200、接触伤害13、半径34的近战敌人；具体战斗属性按模式原规则成长和叠加词条。范围170–430且直线可见时，`core/systems/ai.ts/updateCharge` 记录固定角度并原地预警54tick，进入最多24tick的直线冲刺；冲刺移速为当前移速3倍，最高使整段位移不超过430。墙体或边界会提前终止。结束进入36tick硬直和150tick冷却，然后正常寻路。冲刺阶段不重新瞄准，目标可以侧向躲避。

`Actor.charge` 保存阶段、剩余tick、固定角度和上一位置，`serialization.ts` 校验值域及实体归属；旧存档没有该字段时按未蓄力处理。低画质也绘制预警线及倒计时，线在碰撞墙前裁剪。快照复用 `windupTicks/Angle` 与 `dashing`，受保护者额外带 `supportRelayId`；`net/sync.ts` 字段字典由协议 **prism-server-5** 管理，服务器和浏览器须同步更新。

## 4. 持久化与兼容

没有新增卡片或玩家属性，数值存档版本仍为7；当前房间的设备生命、突进状态、后续波次、主题、无尽生成随机状态和补刷队列均随原World/模式存档保存。旧存档无新增字段仍可读取；旧存档的当前房间继续其已保存状态，尚未进入的房间由当前版本的生成器构造。新版本产生的新敌人状态不能被只认识旧类型的客户端解释，因此实时协议有意不兼容v1.27。

## 5. 回归及尚待验证

`tests/unit/encounters.test.ts` 覆盖种子和防重复、地图通路、多波与设施清关、护甲链可见性、四类武器拆除、资源与吸血边界、冲刺预警/墙体/最大距离、阶段存读确定性、压缩差量同步、无尽有限/开放层和五人合作存档；原地牢/无尽/合作/服务器/武器测试仍运行。数值平衡、移动端密集战场可读性、复杂墙角与五人公网长局需要真人和真机持续试玩，不能仅凭自动化证明最终难度合适。
