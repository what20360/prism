# PRISM 技术手册（八）：联机反馈、移动端与持续电弧

当前实现：v1.27，2026-11-06。敌人与关卡的后续设计单列在[遭遇升级方案](../design/encounter-roadmap.md)，该方案尚未实装。

## 1. 权威输入与本地反馈

服务器仍以60Hz运行真实战斗，以10Hz发送压缩差量；`src/net/serverProtocol.ts` 的实时协议为 **prism-server-4**。客户端与服务器必须一起更新。协议新增 `PlayState.inputAck={sequence,ticks,expired}`，并在Actor字典加入 `channeling`。存档数值版本仍为7，不混用实时协议与存档版本。

- `src/net/control.ts/createRemoteInput`：收包只更新待执行输入。模拟调用 `read()` 才确认该序号，并累计它实际被读取的逻辑帧数；超过350ms没有心跳返回空输入，确认标记过期。不能把“已收到”当“已执行”。
- `src/server/server.ts`：每客户端独立确认、编码器与输入流；广播把确认放在PlayState外层，不放进世界或Snapshot。
- `src/net/sync.ts`：确认随帧头传递，解包时从Snapshot字段中剥离；重连和关键帧处理沿用原规则。
- `src/net/prediction.ts/createLocalPrediction`：保留最多64条、2秒的本机已发送移动记录，扣掉确认已消耗的帧数，重放未执行时间。总提前量最多250ms，拥塞时保留最近方向；350ms无快照则停用预测，避免断线后继续虚走。
- `src/core/systems/movement.ts/moveCircle`：预测与真实移动共用轴向碰撞与边界处理，并按半径/位移细分步长。预测不模拟单位推挤、伤害、拾取、射击命中或钱包，服务器结果始终覆盖本机推测。
- 小误差不超过96世界单位时以65ms指数衰减校正，并再次受墙体约束；较大误差直接对齐。切房、席位变化、菜单/失焦、死亡复活、传送、冲刺等重置或绕过预测。新快照中冲刺结束的状态仍交由服务器。

`src/app/serverSession.ts` 先用预测位置计算鼠标方向，再绘制本机角色即时朝向；其他角色继续使用插值。能量轨迹靠近枪口的首段随本机显示位置修正，终点与伤害仍来自服务器。预测可在设置关闭，用于排查碰撞或网络异常。RTT来自ping/pong平滑估算，不是单程延迟；角落显示等待同步或往返毫秒数。

### 短按与生命周期

浏览器每渲染帧读取输入，网络最多约30Hz发送变化、100ms心跳。`src/net/inputBuffer.ts` 在两次发送之间累积地雷、技能、锁定/取消锁定事件，只有成功发送才清除；菜单、隐藏页面、重连或退出会清空，防止恢复后意外释放技能。持续移动/扳机始终使用最新状态，不把长按积成动作队列。该缓冲不能恢复两个渲染帧之间从未被设备层采样到的事件；触屏地雷/技能在设备层另有pending边沿。

## 2. 手机端的输入与布局

`src/input/touch.ts` 使用每个控件独立pointerId和捕获：移动、瞄准开火、地雷、两个技能可并行，不允许另一根手指的up/cancel/lostcapture释放当前控件。释放捕获前先清owner，避免lostcapture重入。

- 固定摇杆为默认；浮动摇杆在移动侧下方46vw×45dvh区域落指定位，位置受屏幕边缘约束。
- 径向死区默认12%，死区以外重映射至0–100%推进强度；轻推可慢走。
- 瞄准摇杆松手停止手动开火、保留最后朝向；暂停、窗口失焦、隐藏、旋转、改布局清空朝向与按住状态。
- `src/input/pointer.ts` 的战场触摸锁定在松手时判断：350ms内、移动不超过12 CSS像素。滑动、取消不锁定，其他手指松开不打断当前点选。桌面仍为左键开火、右键锁定。
- `requestFullscreen` 仅由玩家点击全屏按钮触发，API不可用时隐藏；拒绝时提示浏览器菜单/主屏幕方式，不强迫全屏或横屏。

`src/storage/config.ts` 设置版本5，可读1–4。新增固定/浮动、左右手、尺寸80–140%、透明度30–100%、死区5–30%、边缘8–60px、独立音乐/音效音量、画质和预测开关，解码时验证/钳制。`src/ui/sections/settings.ts` 按组生成控件，范围输入拖动时只更新数值，释放后提交，避免移动端滑杆拖动被整页重建打断。

`src/app/style.css` 同时考虑 **宽度≤760px或高度≤500px**，使横屏手机也走紧凑布局：横向滑动目录、独立纵向内容、底部固定继续/导航操作、44px触控目标、16px输入框、刘海和Home指示条安全区。左右手交换战斗控件。长收藏列表内部滚动，横屏流派提示移到顶部中间，避免遮住射击区。

`src/render/canvas2d/renderer.ts` 紧凑HUD保留生命、货币、武器、房间/波次、队伍与小地图，压缩目标卡；不重复桌面按键说明。竖屏镜头略向上留出拇指区。Canvas HUD也从CSS读取四边安全区，横屏目标卡放在两摇杆之间，避免刘海和技能按钮遮盖；设置刷新保留纵向滚动位置。低/均衡/高画质控制DPR上限1/1.5/2及装饰拖尾/光晕/飘字，不改变碰撞、敌弹、怪物、地雷和攻击预警。质量选项只减少表现开销，不宣称对所有手机有固定帧率保证。

## 3. 持续电弧与DPS守恒

入口为 `src/core/systems/weapons.ts/updateWeapons`，树搜索仍为 `energyWeapons.ts/fireElectric`：全方向根选择、每棵树独立穿透、每条树无环、深度衰减、传导距离0.8R、墙体阻挡都保留。

设旧电弧一次完整攻击对某节点的原始伤害为D，目标固定格挡B，旧冷却逻辑帧为 **C=max(1,round(60/fireRate))**。现在按住攻击每帧累积1/C份额，每6帧刷新一次电流，首次按下立即结算一帧份额，松手结清已累计的余量，不预支后续伤害，也不积蓄空闲时间。

持续n帧共分配n/C份额。一次刷新份额为q时：

- 原始伤害为Dq；
- `applyDamage` 的 `blockScale=q`，固定格挡消耗为Bq；
- 后续穿甲、护甲、电抗性、护盾、生命处理沿用原管线。

因此固定目标/属性/遮挡条件下，伤害为 `max(0,D-B)×(n/C)×护甲倍率×电抗倍率`。旧每发格挡的强度完整保留，不因刷新10次/秒而额外扣十遍完整格挡，也不对高格挡敌人提供无条件穿透。其余武器未传blockScale，默认1，不受影响。无需另加会改变原有DPS的持续破甲叠层。

这个守恒指稳定战斗，不等于每一秒的瞬时伤害相同：旧式整发在开始时提前给完整伤害，现在只给实际供能时长；击杀时间、换目标、失去视线、溢出与击杀掉落可能不同。电击减速会随持续命中刷新，属于持续攻击的控制差异，应继续实战观察。

Actor可选 `electricBudget/electricTimer` 随存档保存；旧文件缺省0，严格验证有限数和周期边界。换武器、死亡、断线、训练重置清空未结预算。快照 `channeling` 驱动电弧枪口动画；不显示伪造的普攻冷却环。轨迹强度使用等效整发威力，不因分段变暗；细小伤害显示小数，避免全部飘0。每玩家刷新替换自己的电弧轨迹，装饰命中效果/飘字有数量边界。音频每类武器独立节流，电弧连续嘶声不会被队友弹芯枪音效挤掉。
