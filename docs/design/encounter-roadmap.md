# 敌人与关卡：从清场重复到遭遇决策

本文保留v1.27研究时的设想。v1.28实现主题编队、突击者与继电站；v1.29实现闸廊、矿室、封路者和召援者。下文原始提案可能与最终实现不同，现行规则见[第九篇](../technical/09-encounters-and-enemies.md)及[第十篇](../technical/10-objectives-and-support.md)。

## 1. 重复感来自哪里

| 当前实现与位置 | 对玩法的影响 |
|---|---|
| `content/levelSets.ts`：3套普通布局＋盘丝洞Boss；安全屋单独模板 | 普通房间的形状和路线变化少，随机布局并未改变玩家任务 |
| `content/dungeon.ts/buildDungeon`：5层×5房＋Boss；普通房间重复从同池抽怪、按难度/深度放大数值、数量和波次 | 大多数房间的唯一终点是清完所有波，进程缺少不同节奏和主动选择 |
| `content/dungeon.ts/populateWave`：各个敌人约78%机会从palette替换，位置主要随机合法摆放 | 有怪物种类，但组合缺少明确战术主题；远近角色容易随机扎堆 |
| `core/systems/ai.ts`：近战绕障追最近目标、游猎横移、灼线蓄能；`weaver.ts`包含完整Boss/小蜘蛛循环 | 大多数普通怪通过逼近/射击施压，角色配合与阶段转换有限；Boss相对有明确节奏 |
| `content/monsterTraits.ts`：树皮、迅捷、铁壁、电涌、灼热、自爆；属性型词条占多数 | 容易把变化表现为更耐打、更快，缺少可读的行为差异 |
| `app/modes/endless.ts`：有限层清场、每5层无限补怪且出口常开；同类随机模板/数值分布 | 开放层有收益/风险选择，但仍缺少具体遭遇叙事，长局不断加血量不能持续提供新决策 |

现有游猎射手、灼线哨兵、铁壁卫士、电弧游骑、自爆体和盘丝母巢已有机制，应优先组合与调校。无需先造二十种新皮肤，也不应通过大幅加速弹幕来抵消手机操作空间。

## 2. 设计目标与边界

每个遭遇至少提供一个可理解的选择：先杀谁、借哪块掩体、何时推进、是否承担额外风险。基础弹芯枪、狙击、持续电弧、激光和雷阵都应有可行解；敌人允许擅长克制某流派，但不出现完全免疫造成单武器软锁。

把难度分成三件事：属性预算、同时威胁预算、配合复杂度。高难度可增加组合复杂度与容错压力，但保留可见预警和能走通的安全方向；1档沿用当前基础战斗强度。多人主要增加侧翼/任务分工，不能让五人队在五倍重叠预警里硬吃伤害。

不引入局外数值养成、抽卡商店或强迫等待的护送。随机种子生成结果可重现，读档不能重刷奖励。无尽开放层的无上界强怪与奖励递减继续保留；新的安全/公平预算只约束生成位置、同时压迫和行为时间，不能偷偷截断开放层属性分布。

## 3. 第一阶段：已有敌人的编队与节奏（v1.28已实现主题组合）

先做内容数据化的 `EncounterSpec`，不要把房型判断散落到AI。建议新增 `content/encounters.ts` 与 `core/encounter.ts`，将编队分为：

| 编队 | 组合、空间关系 | 玩家决策 | 限制 |
|---|---|---|---|
| 掩体夹击 | 两侧游猎＋后方炮台，近战在侧翼入口 | 借掩体切断炮台，先清一翼获得退路 | 初始不同时封死两条路线；至少一个可达安全扇区 |
| 重甲护送 | 铁壁/树皮前排＋后排灼线哨兵 | 绕前排优先打蓄能者，或用穿透贯通 | 不叠满屏格挡，后排不能一直隔墙命中 |
| 引爆窗口 | 少量自爆体＋慢速远程 | 利用自爆后空档推进，或提前远杀 | 自爆预警不短于现有规则；死亡弹幕有醒目标志 |
| 雷场拉扯 | 电弧游骑＋移动近战，地形给局部遮挡 | 地雷清弹/控速、移动切断连锁路线 | 不把整个房间铺满无法避开的导电攻击 |

已实现按难度/层数解锁角色、左右分区出生；闯关避免最近两次主题，无尽按种子循环避免最近两层重复。按实际战斗压力动态安排休整尚待实测与开发。

波次仍在清场后预警1.5秒；允许小批增援，但增援总数有限，开局确定预算且不可无限刷钱。最后一名残余敌人可在小地图提示，不用瞬移清除、无条件给出口或缩短寻路来掩盖卡墙。

## 4. 第二阶段：三个有明确用途的新敌人（突击者已实现，其余待研究）

| 敌人提案 | 行为与反制 | 视觉/手机可读性 | 首版限制 |
|---|---|---|---|
| 棱镜接线员 | 在有视线的邻近敌人间维护有限护甲链接；击断链接或击杀它暂时削弱被保护者。自身较脆 | 有方向的细链接＋独特菱形核；不得仅用红绿颜色区别 | 最多保护2个；不无限回血、不复活、不能互保成环；任何武器可击杀 |
| 裂隙突击者 | 先标出冲刺通道，再短冲，撞墙或结束后硬直；预测点在预警开始后固定 | 地面窄带与起点充能环，保持约0.8–1秒反应窗口作为初始调参值 | 每组最多1–2个；突进期间不追踪拐弯；不从屏幕外无预警冲撞 |
| 封路织者 | 朝一个区域投放短寿命危险带，迫使换掩体；被打断后取消本次部署 | 地面虚线铺设→实线激活→碎裂消失，区别于可拾取资源 | 不同时封死所有出口；危险带有总覆盖预算，不永久铺场，不再生奖励 |

时间为设计起点而非已定平衡数值。先在测试模式提供单敌、组合敌与预警开关比较，确认键鼠和手机都看得懂再加入正式池。新行为状态必须进存档与Snapshot；AI决策使用逻辑tick/PRNG，不用浏览器时间。不要为了多样性把所有单位同时改成高血高格挡。

## 5. 第三阶段：三个差异化房间原型

### 折光继电站：先破装置还是强攻（v1.28已实现）

双环可绕行路线，中间有掩体和两座脆弱继电装置。装置支援有限守军，破坏后停止对应支援，清理守军后出口打开。装置是可攻击中立目标，任何武器/地雷都能处理，不能强迫靠近按键；大伤害构筑可以直接强攻守军，不因没有范围伤害而卡关。

首版继电器提供固定护甲，最多各保护两名视线内的非首领；连线显示保护关系。装置占原生成槽，可被各种伤害击毁，不提供伤害经济、击杀奖励或吸血；守军全灭即关闭设备、允许通关。

### 交错闸廊：推进改变战场（v1.29已实现，细节见第十篇）

两条相通侧路、两处推进节点。靠近节点触发一组有限增援，清理后打开下一段，不用固定站圈等待。玩家选择左/右路决定侧翼角度，进入下一段前保留回撤空间。多人不要求五人挤在同一个按钮上；任意存活成员触发，触发状态由服务器一次性提交。

禁止在门后立刻刷怪堵住玩家；每段预览出口方向和增援范围。性能预算按同时存活数，而非累计刷怪数制定。

### 不稳定矿室：有限收益的可选风险（v1.29已实现，细节见第十篇）

主路短遭遇清理即可开出口；旁路矿核可选触发一次额外精英编队，成功获得固定预算资源/后续路线情报。可以不打，不把奖励塞在漫长跑图角落；警示卡标明额外风险，不把无法预期的高层怪塞进普通闯关。

一房一次、存档保留已激活/已领取；额外敌人收入纳入本房总预算，不能激活后切房/读档重领。无尽开放层继续自己的长尾分布和补刷递减，附加奖励不能把递减洗回1。

## 6. 数据结构与实施位置

原研究时建议接口（以下为进一步扩展备选，不是现有接口）：`EncounterSpec {id,layoutId,roles,groups,threatBudget,objective,rewardBudget}`；`EncounterState {id,phase,triggeredGroups,objectiveStates,rewardClaimed,rngState}`。角色槽描述锚点、角色、数量、触发条件，生成器输出已有 `EnemySpawnSpec`，无需改每张卡。

| 工作 | 主要入口 | 兼容要求 |
|---|---|---|
| 布局/导航 | `content/levelSets.ts`、`core/navigation.ts` | 对每种半径检查出生/目标/出口连通，碰撞不重叠；手机可见预警 |
| 预算和生成 | `content/dungeon.ts`、`content/difficulties.ts`、`app/modes/endless.ts` | 难度/人数/层数共同定预算；有限层属性上限仍逐项核验，开放层不加属性截断 |
| 行为 | `core/systems/ai.ts`及新独立行为模块 | 预警、执行、硬直状态机；对可控1v1演员不误执行AI |
| 推进/目标 | `core/systems/room.ts`、`core/dungeon.ts`、模式适配 | 旧无objective房间默认清场；一次触发/领取由权威模拟决定 |
| 显示 | `core/snapshot.ts`、`net/sync.ts`、渲染器/HUD | 小目标列表最多2项；复杂详情放菜单，不挡触屏；更新协议字典 |
| 存档 | `core/serialization.ts`、`app/checkpoints.ts`与合作存档 | 显式新版本迁移；旧存档继续原房间流程，不能读档重新抽遭遇 |

重连、团灭、读档必须保留节点触发、装置死亡、奖励领取和增援队列。离线成员不成为关门条件。强制切房前收尾目标事务，不能两人同时踩节点生成两批增援。

## 7. 验收与开发顺序

1. **已完成4套现有敌人编队与反重复选择**，加种子回归、连通性、出生安全与多人预算测试。用同一金额的五类构筑、1档/4档/7档、1/3/5人比较。
2. **已实现一个新敌人：裂隙突击者**。它能以预警/硬直直接增加操作决策，不先引入复杂链接同步。真实手机验证可躲避后再放进池。
3. **已实现一个战术目标房：继电站**。先让地图与目标改变打法，确认存档、切房和奖励无漏洞，v1.29又加入选路闸廊与可选矿室，尚需试玩。
4. 可在玩家自愿同意的前提下研究汇总遭遇数据；当前尚未实现采集，详见[平衡验证方案](balance-evidence.md)。调整依据是实玩与数据，不是理论DPS单项排名。

验收建议：连续6个普通遭遇不出现3次同主题连刷；玩家进入后能在约3秒识别主要威胁与出口方向；普通敌人没有隔墙/屏幕外无预警必吃伤害；五人刷怪倍率不造成全屏持续封路；同种子读档/重连的最终世界哈希与领取资源一致。帧率与带宽目标需用指定手机/网络记录中位值和低分位，再定可承诺指标，不能用桌面单测时间冒充真机结果。
