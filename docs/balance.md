### 1.1 护甲 → 减伤换算

```
减伤 = 护甲 / (100 + 护甲)
```

| 护甲 | 减伤 |
|---|---|
| 0 | 0% |
| 50 | 33.3% |
| 100 | 50.0% |
| 200 | 66.7% |
| 300 | 75.0% |
| 600 | 85.7% |
| 900 | 90.0% |
| ∞ | → 100%（永不达到） |

- 减伤是**派生值**，不作为独立属性存储。
- 收益天然递减，因此**不需要封顶**，也不会出现无敌。
- 护甲穿透：`有效护甲 = max(0, 护甲 - 穿透)`，再代入上式。

## 5. 棱晶收益（按伤害结算）

### 5.1 结算公式

```
输出收益 = round((实际伤害 + 溢出伤害 × 0.5) × tierRate × chainMultiplier)
受伤收益 = round(敌方来源的减免前伤害 × takenRate)   // takenRate = 0.05
shardGain = 输出收益 + 受伤收益
```

- 收益与**击杀无关**，每点伤害都产生收益。
- 溢出伤害按 **50%** 计入（奖励高爆发与单发高伤害）。
- 内层伤害 ×1.5 已自动转化为更多收益，不再有额外汇率。
- **承伤同样产生收益**，按减免前伤害计算，见 5.6。

### 5.2 敌人等级系数

| 敌人等级 | tierRate（棱晶/伤害） |
|---|---|
| 普通敌人 | 0.10 |
| 精英 / 层守卫 | 0.12 |
| 最终 Boss | 0.05 |
| 召唤物 / 分裂体 | 0.10 |

### 5.3 连杀

`chain = min(2.0, 1 + 0.1 × (n - 1))`，间隔 > 3 秒或掉血中断。

### 5.4 房间奖励

| 项 | 棱晶 |
|---|---|
| 清空房间 | +10 |
| 无伤清空房间 | 额外 +5 |

### 5.5 收入结构估算

| 项 | 估算 |
|---|---|
| 普通房（8 小怪 × 30 HP） | 240 伤害 × 0.10 × 1.4 ≈ **34**（输出） |
| 普通房承伤（约 15 次命中 × 10 减免前伤害） | 150 × 0.05 ≈ **8**（受伤） |
| 守卫房（Warden 220 HP） | 220 × 0.12 × 1.4 ≈ **37** + 承伤约 10 |
| 每层（4 普通 + 1 守卫） | 输出 ≈ 173 + 受伤 ≈ 42 + 清房 45 ≈ **260** |
| 五层合计 | ≈ **1300** |
| 最终 Boss（2000 HP） | 2000 × 0.05 × 1.4 ≈ **140** + 承伤 |

| 项 | 目标 |
|---|---|
| 输出收益占比 | ≥ 50% |
| 受伤收益占比 | ≤ 20% |
| 清房奖励占比 | ≤ 35% |

> 按上表：输出 ≈ 870 / 受伤 ≈ 210 / 清房 ≈ 225（合计约 1305）→ 约 67% : 16% : 17%，符合目标。

### 5.6 受伤收益（takenRate）

| 规则 | 取值 |
|---|---|
| 计算基数 | **减免前**伤害（护甲减伤前、护盾吸收前） |
| 来源限制 | 只计**敌方来源**；自伤（自己的地雷、环境）不计 |
| 无敌帧 | 被无敌帧挡开的命中不计 |
| 护盾吸收 | **计入** |
| 系数 | `takenRate = 0.05`（约为普通敌人 tierRate 的一半） |
| 连杀 | 不乘 `chainMultiplier`；受伤本身会中断连杀 |

**单次收益参考**

| 敌方攻击 | 减免前伤害 | 获得棱晶 |
|---|---|---|
| 小怪子弹 | 8 | 0.4 |
| 精英子弹 | 12 | 0.6 |
| Boss 大招 | 40 | 2.0 |

> 意图：防御流靠「挨打」拿到的收入约为纯输出流的 1/4～1/3，足以让护甲路线不亏，但不足以让「站着挨打」成为最优解。

## 6. 升级卡片

### 6.1 价格规则

**价格只与购买次数有关**，不读取任何属性：

```
cost(level) = round(base × growth^(level-1))，growth = 1.6
```

- 卡片可以**捆绑其他属性销售**（正面 + 负面），但捆绑内容不影响价格。

## 9. 校准决策记录

### 第一轮

| 议题 | 结论 |
|---|---|
| 射速手感 | 1.8 → **1.2 发/秒**；仍偏快则取 1.0 |
| 地雷清弹过强 | 不削伤害，**优先提高布置冷却**（2 → 3 秒） |
| 地雷「必吃伤害」 | 设计上不是惩罚：范围必须可视化，玩家应绕开 |
| 内层面积 | 20% 合理 |
| 减伤无敌风险 | 允许极端构筑（玩法核心），靠价格 / 怪物 / 卡片数值平衡 |
| 吸血/吸盾 | 允许重度吸血「几乎不躲」，但 Boss 近身硬吃仍会暴毙 |
| 穿透打内层的理解成本 | 相信玩家；但展示必须充分（命中特效、飘字、面板说明） |
| 房间尺寸 | 桌面主流 1920×1080；射程 = 房间宽度 50%；加入墙体，为弹射预留 |

### 第二轮

| 议题 | 结论 |
|---|---|
| 减伤机制 | 引入**护甲值**，`减伤 = 护甲/(100+护甲)`，天然渐近 100% |
| 卡片定价 | 卡片可捆绑其他属性，但**价格只与购买次数有关** |
| 吸盾 | **不与自身减伤挂钩**；改由「护盾上限 = 最大生命 × 系数」约束 |
| 数值溢出 | 不必过度防御，通过价格、怪物数值、卡片数值调节；探索强力方案是核心玩法 |
| 收益来源 | **按伤害而非击杀**；溢出伤害按 50% 计入收益 |

### 第三轮

| 议题 | 结论 |
|---|---|
| 承伤是否产生收益 | **产生**，且按**减免前**伤害计算（`takenRate = 0.05`），使防御构筑具备经济回报 |
| 承伤的边界 | 只计敌方来源；自伤与无敌帧挡开的命中不计；护盾吸收计入 |

### 第四轮

| 议题 | 结论 |
|---|---|
| 实体尺寸 | 玩家与敌人放大到约 **2.2 倍**（玩家半径 18→40，小怪 16→34） |
| 地图与镜头 | 房间放大到 **3200×1800**，视野窗口固定 1920×1080，相机跟随玩家并夹紧在房间内 |
| 射击手感 | 射速 1.2→**0.8**、射程 960→**560**、弹速 900→**700**，让接近与开火时机成为决策 |
| 地雷 | 半径同步放大（本体 30 / 爆炸 200），触发与减速场改为**爆炸半径的 60%（120）**并通过单一比例变量联动 |
| 偏转 | 改为**被动充能偏转**（按速率侧偏，归属不变）+ **主动反弹**（窗口内反向并夺回归属，Lv2 加伤害） |

### 第五轮

| 议题 | 结论 |
|---|---|
| 射速 | 0.8 → **0.7 发/秒**，进一步给「射速卡」留成长空间 |
| 被动偏转 | 从「充能次数」改为**连续力场**：场内敌方子弹每帧受背离玩家的加速度，越近越强（`strength × (1-d/R)²`） |
| 力场参数 | 半径 220、强度 600（圆心处），偏转卡每级 +40 半径 / +150 强度 |
| 主动技能 | 窗口内力场 ×5，并把接触子弹反向回射、归属转为玩家 |

### 第六轮

| 议题 | 结论 |
|---|---|
| 玩家生命 | 100 → **50**：让「挨打」重新变得昂贵，配合护甲/护盾/吸血卡的取舍 |
| 地雷半径 | 触发与减速场 ∈ **爆炸半径 × 0.6（200 → 120）**，两者共用一个比例变量，只调一个数 |
| 地雷上限 | 满 3 颗后继续布置 → **替换最早的一颗**，而不是布置失败（避免"明明按了却没反应"） |
| 界面按键 | 收敛为**单一菜单键 `Esc`**：左侧目录切换帮助 / 按键绑定 / 升级面板 / 角色属性，不再为每个面板新增按键 |
| 卡片信息 | 价格不足不写字，改**价格变色**；每张卡常显「下一级数值 + 前置条件」 |
| 出生点 | 内容锚点重新选点，运行时再加 `resolveSpawnPosition` 兜底，杜绝敌人卡在墙里 |
